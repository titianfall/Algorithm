# 무식하게 풀기: 완전 탐색과 재귀

> 쉬운 문제를 굳이 어렵게 풀고 있지는 않은가?  
> 답이 작다면, 가장 단순하게 **모든 경우를 직접 확인하는 방법**부터 생각해보자.

## 이 디렉토리의 학습 목표

이 디렉토리의 예제들은 모두 **완전 탐색을 재귀 호출로 구현하는 방법**을 연습하기 위한 코드이다.

- [pick.cpp](<pick.cpp>): 반복문으로 중첩되던 조합 생성을 재귀로 일반화한다.
- [boggle.cpp](<boggle.cpp>): 보드의 모든 시작점과 8방향 이동을 재귀로 탐색한다.
- [picnic.cpp](<picnic.cpp>): 짝짓기 경우의 수를 세면서 중복 탐색을 줄이는 방법을 익힌다.
- [boardCover.cpp](<boardCover.cpp>): 블록을 놓고, 재귀 호출하고, 다시 되돌리는 백트래킹을 연습한다.
- [TSP.cpp](<TSP.cpp>): 도시 방문 순서를 모두 만들어 보며 최단 경로를 찾는다.
- [clockSync.cpp](<clockSync.cpp>): 각 스위치를 0~3번 누르는 모든 조합을 확인한다.

완전 탐색과 재귀 호출을 익힌 뒤에는 보글 문제를 사용해 추가 학습을 진행한다.

- 문제 사이트: [Algospot BOGGLE](<https://algospot.com/judge/problem/read/BOGGLE>)
- 풀이 코드: [boggle.cpp](<boggle.cpp>)

짝짓기 문제를 통해 완전 탐색에서 자주 발생하는 **중복 세기 오류**를 익힌다.

- 문제 사이트: [Algospot PICNIC](<https://algospot.com/judge/problem/read/PICNIC>)
- 풀이 코드: [picnic.cpp](<picnic.cpp>)

## 1. 무식하게 풀기란?

컴퓨터는 사람이 하기 어려운 반복 계산을 매우 빠르게 처리할 수 있다.  
따라서 가능한 경우의 수가 충분히 작다면, 모든 경우를 하나씩 확인해서 답을 찾는 방법이 좋은 출발점이 된다.

이런 풀이 방식을 보통 다음과 같이 부른다.

- **완전 탐색**: 가능한 모든 경우를 빠짐없이 확인하는 방법
- **Brute Force**: 힘으로 밀어붙이듯 모든 후보를 검사하는 방법
- **Exhaustive Search**: 전체 탐색

완전 탐색은 가장 단순하지만, 문제의 구조를 이해하는 데 매우 강력하다.  
먼저 무식하게 풀 수 있는지 확인한 뒤, 너무 느리다면 그때 가지치기나 동적 계획법 같은 최적화를 고민하면 된다.

## 2. 재귀 호출이 필요한 이유

컴퓨터가 수행하는 작업은 대개 더 작은 작업들로 나눌 수 있다.

예를 들어 `1 + 2 + ... + n`을 구하는 문제는 다음처럼 생각할 수 있다.

```text
sum(n) = n + sum(n - 1)
sum(1) = 1
```

이처럼 큰 문제를 같은 형태의 작은 문제로 줄일 수 있을 때, **재귀 함수**를 사용할 수 있다.

- **Recursive Function**: 자기 자신을 다시 호출하는 함수
- **Recursion**: 재귀 호출

재귀는 반복문으로도 표현할 수 있는 경우가 많다.  
하지만 조합, 순열, 그래프 탐색, 백트래킹처럼 “선택하고 다음 단계로 들어가는 문제”에서는 재귀가 훨씬 자연스럽다.

## 3. 반복문으로 1부터 n까지 더하기

```cpp
int sum(int n) {
    int ret = 0;

    for (int i = 1; i <= n; i++) {
        ret += i;
    }

    return ret;
}
```

반복문 방식은 `1`부터 `n`까지 차례대로 더한다.  
흐름이 눈에 잘 보이고, 단순한 누적 계산에 적합하다.

## 4. 재귀로 1부터 n까지 더하기

```cpp
int recursiveSum(int n) {
    if (n == 1) return 1;
    return n + recursiveSum(n - 1);
}
```

재귀 함수에는 반드시 멈추는 조건이 필요하다.

```cpp
if (n == 1) return 1;
```

이 부분을 재귀 호출의 **기저 사례(base case)**라고 한다.  
기저 사례가 없으면 함수가 끝없이 자기 자신을 호출하게 된다.

단순한 반복문을 사용하는 방법과 재귀 함수를 사용하는 사례는 [pick.cpp](<pick.cpp>)에 정리했다.

## 5. 완전 탐색 재귀의 기본 구조

완전 탐색 재귀는 보통 다음 흐름을 가진다.

```cpp
int search(State& state) {
    if (끝까지 만든 상태라면) {
        return 답;
    }

    int ret = 초기값;

    for (가능한 선택 choice : choices) {
        선택을 적용한다;
        ret = 답을 갱신한다(search(state));
        선택을 되돌린다;
    }

    return ret;
}
```

이 구조에서 중요한 부분은 네 가지이다.

- **상태(state)**: 지금까지 어떤 선택을 했는지 저장한다.
- **기저 사례(base case)**: 더 이상 선택할 것이 없을 때 답을 반환한다.
- **선택(choice)**: 현재 상태에서 다음으로 시도할 수 있는 후보이다.
- **되돌리기(undo)**: 재귀 호출이 끝난 뒤 이전 상태로 복구한다.

`push_back()`을 했다면 `pop_back()`을 하고, `visited[i] = true`를 했다면 다시 `false`로 돌려놓는다.  
이 되돌리기 과정 때문에 하나의 배열이나 벡터를 여러 재귀 경로에서 재사용할 수 있다.

## 6. 예제별 재귀 흐름

### pick.cpp

`pick.cpp`는 여러 개 중 몇 개를 고르는 조합 문제이다.

- 상태: 지금까지 고른 숫자 목록 `picked`
- 기저 사례: 더 골라야 할 개수 `toPick`이 0이 되는 경우
- 선택: 다음에 고를 수 있는 숫자
- 되돌리기: `picked.pop_back()`

반복문을 여러 겹 직접 쓰면 고르는 개수가 바뀔 때마다 코드를 다시 짜야 한다.  
재귀로 만들면 `toPick` 값만 바꿔서 같은 구조를 사용할 수 있다.

### boggle.cpp

`boggle.cpp`는 현재 칸에서 단어의 첫 글자를 맞추고, 남은 단어를 8방향으로 계속 찾아가는 문제이다.

- 상태: 현재 좌표 `(y, x)`와 아직 찾아야 하는 문자열
- 기저 사례: 범위를 벗어남, 글자가 다름, 단어 길이가 1이 됨
- 선택: 상하좌우와 대각선을 포함한 8방향
- 답 갱신: 한 방향이라도 성공하면 `true`

이 문제는 답이 존재하는지만 확인하면 되므로, 모든 경우의 수를 세지 않고 성공하는 순간 바로 `true`를 반환할 수 있다.

### picnic.cpp

`picnic.cpp`는 아직 짝이 없는 학생 중 가장 번호가 빠른 학생을 고정하고, 그 학생과 짝지을 수 있는 학생을 모두 시도한다.

- 상태: 각 학생이 이미 짝을 찾았는지 나타내는 `taken`
- 기저 사례: 모든 학생이 짝을 찾은 경우
- 선택: `firstFree`와 짝이 될 수 있는 학생 `pairWith`
- 되돌리기: 두 학생의 `taken` 값을 다시 `false`로 바꿈

여기서 핵심은 **가장 번호가 빠른 남은 학생을 먼저 고정하는 것**이다.  
이렇게 해야 `(0, 1), (2, 3)`과 `(2, 3), (0, 1)`처럼 순서만 다른 같은 짝짓기를 중복해서 세지 않는다.

### boardCover.cpp

`boardCover.cpp`는 아직 덮지 않은 가장 왼쪽 위 칸을 고르고, 그 칸을 포함하는 네 가지 블록 모양을 모두 시도한다.

- 상태: 현재 보드의 덮임 상태 `board`
- 기저 사례: 더 이상 빈 칸이 없는 경우
- 선택: 네 가지 블록 모양 `coverType`
- 되돌리기: `set(board, y, x, type, -1)`

이 문제는 재귀 호출 전후의 상태 복구가 특히 중요하다.  
블록을 놓아 보고 실패하거나 탐색이 끝나면 반드시 다시 치워야 다음 블록 모양을 올바르게 시도할 수 있다.

### TSP.cpp

`TSP.cpp`는 시작 도시를 고정한 뒤, 남은 도시들의 방문 순서를 전부 만들어 보는 문제이다.

- 상태: 지금까지 방문한 경로 `path`, 방문 여부 `visited`, 현재 길이 `currentLength`
- 기저 사례: 모든 도시를 방문한 경우
- 선택: 아직 방문하지 않은 다음 도시 `next`
- 답 갱신: 가능한 경로 길이 중 최솟값
- 되돌리기: `visited[next] = false`, `path.pop_back()`

`INF`는 최솟값을 구하기 전에 임시로 넣어 두는 매우 큰 값이다.  
`cout << fixed << setprecision(10)`의 `fixed`는 `INF`와 관련된 값이 아니라, 실수를 고정 소수점 형식으로 출력하기 위한 표준 출력 조작자이다.

### clockSync.cpp

`clockSync.cpp`는 10개의 스위치를 각각 몇 번 누를지 정하는 문제이다.

- 상태: 현재 16개 시계가 가리키는 시각 `clocks`
- 기저 사례: 10개 스위치에 대한 선택이 모두 끝난 경우
- 선택: 현재 스위치를 0번, 1번, 2번, 3번 누르는 네 가지 경우
- 답 갱신: 가능한 방법 중 누른 횟수의 최솟값
- 되돌리기: 같은 스위치를 총 4번 누르면 원래 상태로 돌아온다.

이 문제에서 재귀의 깊이는 시계 번호가 아니라 **스위치 번호**이다.

```text
0번 스위치를 몇 번 누를지 결정
1번 스위치를 몇 번 누를지 결정
2번 스위치를 몇 번 누를지 결정
...
9번 스위치를 몇 번 누를지 결정
```

한 스위치를 누르면 연결된 시계들이 모두 `3시간`씩 앞으로 움직인다.

```text
12 -> 3 -> 6 -> 9 -> 12
```

따라서 같은 스위치를 4번 누르면 아무것도 누르지 않은 것과 같아진다.  
그래서 각 스위치는 0번부터 3번까지만 눌러 보면 충분하다.

`solve(clocks, swtch)`는 다음과 같이 해석하면 된다.

```text
swtch번 스위치부터 마지막 스위치까지 눌러서
모든 시계를 12시로 만들 수 있는 최소 누름 횟수
```

기저 사례에서 모든 시계가 12시라면 `0`을 반환하고, 아니라면 `INF`를 반환한다.  
그 위 단계에서는 `cnt + solve(clocks, swtch + 1)`로 현재 스위치를 누른 횟수와 나머지 스위치로 맞추는 최소 횟수를 더한다.

## 7. 시간복잡도는 재귀 호출 트리 전체를 본다

재귀 코드에서 `for`문이 한 번 보인다고 해서 전체 시간복잡도가 단순히 `O(n)`이 되지는 않는다.  
중요한 것은 **그 for문 안에서 재귀 호출이 몇 갈래로 다시 뻗어 나가는지**이다.

예를 들어 `TSP.cpp`는 한 호출 안에서 다음 도시 후보를 `n`번 확인한다.  
하지만 실제로는 다음과 같이 방문 순서를 계속 만들어 간다.

```text
처음에는 n - 1개 중 하나 선택
그다음에는 n - 2개 중 하나 선택
그다음에는 n - 3개 중 하나 선택
...
```

따라서 시작 도시를 고정하면 가능한 경로 수는 대략 `(n - 1)!`개가 된다.  
그래서 TSP 완전 탐색은 보통 `O(n!)`으로 본다.

다른 예제들도 같은 방식으로 생각하면 된다.

- `pick.cpp`: 조합의 개수만큼 탐색한다.
- `boggle.cpp`: 단어 길이를 `L`이라고 하면 한 시작점에서 최악의 경우 `O(8^L)`에 가깝다.
- `picnic.cpp`: 중복을 제거하면 대략 `O((n - 1)!!)` 형태가 된다.
- `boardCover.cpp`: 빈 칸을 세 칸씩 덮으므로 최악의 경우 대략 `O(4^(빈칸 수 / 3))`으로 볼 수 있다.
- `TSP.cpp`: 도시 방문 순열을 모두 보므로 `O(n!)`이다.
- `clockSync.cpp`: 10개 스위치가 각각 4가지 선택을 가지므로 `O(4^10 * 16)` 정도로 볼 수 있다.

완전 탐색 문제를 풀 때는 먼저 가능한 경우의 수를 계산해 보고, 그 수가 충분히 작을 때만 이 방식으로 제출할 수 있다.

## 8. 다음에 풀어볼 만한 문제

다음 문제로는 프로그래머스의 [피로도](<https://school.programmers.co.kr/learn/courses/30/lessons/87946>)를 추천한다.

이 문제는 현재 피로도와 던전 목록이 주어졌을 때, 던전 방문 순서를 완전 탐색해서 최대 몇 개의 던전을 탐험할 수 있는지 구하는 문제이다.

`CLOCKSYNC`와 비교하면 다음 감각을 이어서 연습할 수 있다.

- `CLOCKSYNC`: 스위치 10개에 대해 각 스위치를 0~3번 누르는 선택
- `피로도`: 아직 방문하지 않은 던전 중 다음에 방문할 던전을 고르는 선택

둘 다 핵심은 같다.

```text
현재 상태를 저장한다
가능한 선택을 하나 적용한다
재귀 호출로 다음 선택을 진행한다
호출이 끝나면 이전 상태로 되돌린다
```

특히 `피로도`는 던전 수가 최대 8개라서 순열 완전 탐색으로 접근하기 좋다.  
`push/pop`, `visited`, `최댓값 갱신`을 연습하기에 적당하다.
