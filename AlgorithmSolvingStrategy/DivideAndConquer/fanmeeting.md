# 팬 미팅 (FANMEETING)

- 출처: [Algospot FANMEETING](https://algospot.com/judge/problem/read/FANMEETING)
- 분류: 분할 정복, 카라츠바 곱셈
- 시간 제한: 15,000 ms
- 메모리 제한: 65,536 KB

<details>
<summary>문제 설명</summary>

<br>

아이돌 그룹 하이퍼시닉이 팬 미팅을 연다. 멤버들이 무대에 한 줄로 서고, 팬들이 오른쪽 끝 멤버부터 시작해 왼쪽으로 이동하며 각 멤버와 포옹한다. 팬들은 모두 **동시에 한 칸씩** 움직인다.

- 남성 멤버는 남성 팬과 포옹하기 껄끄러워하므로, 이 경우에만 **악수**를 한다.
- 그 외의 모든 조합(남성-여성, 여성-남성, 여성-여성)은 **포옹**을 한다.

멤버와 팬들의 성별이 주어질 때, **모든 멤버가 동시에 포옹하는 일이 몇 번이나 있는지** 세면 된다.

## 인사가 이루어지는 과정

팬들이 이동하는 동안, 모든 멤버가 각자 팬 한 명과 마주 보는 시점에만 "모든 멤버가 포옹"이 가능하다. 멤버 수가 `N`, 팬 수가 `M`이라면 이런 시점은 총 `M - N + 1`번 있다.

첫 번째 예제인 멤버 `FFFMMM`, 팬 `MMMFFF`은 멤버와 팬 수가 같으므로 마주 보는 시점이 한 번뿐이다.

```text
멤버 : F F F M M M
       | | | | | |
팬   : M M M F F F
인사 : 포 포 포 포 포 포   -> 모든 멤버가 포옹 (1번)
```

남성끼리 마주 본 쌍이 하나도 없으므로 이 시점은 조건을 만족한다. 따라서 답은 `1`이다.

세 번째 예제인 멤버 `FFFFM`, 팬 `FFFFFMMMMF`은 마주 보는 시점이 `10 - 5 + 1 = 6`번이다. 그중 남성 멤버가 남성 팬과 만나지 않는 시점은 2번뿐이다.

```text
시점 0 : F F F F M      시점 1 : F F F F M
         | | | | |               | | | | |
         F F F F F               F F F F M
         포 포 포 포 포  -> 성공     포 포 포 포 악  -> 실패
```

## 입력

첫 줄에 테스트 케이스 수 `C`가 주어진다. (`C ≤ 20`)

각 테스트 케이스는 두 줄로 구성된다.

- 첫 줄: 멤버들의 성별을 왼쪽부터 나타낸 문자열
- 둘째 줄: 팬들의 성별을 왼쪽부터 나타낸 문자열

성별은 남성이 `M`, 여성이 `F`이다.

- 멤버 수와 팬 수: 각각 `1` 이상 `200,000` 이하
- 멤버 수는 항상 팬 수 이하다.

## 출력

각 테스트 케이스마다 모든 멤버가 동시에 포옹하는 횟수를 한 줄에 출력한다.

## 예제 입력

```text
4
FFFMMM
MMMFFF
FFFFF
FFFFFFFFFF
FFFFM
FFFFFMMMMF
MFMFMFFFMMMFMF
MMFFFFFMFFFMFFFFFFMFFFMFFFFMFMMFFFFFFF
```

## 예제 출력

```text
1
6
2
2
```

## 1. 무식하게 푸는 방법

멤버 수를 `N`, 팬 수를 `M`이라고 하자. 팬들이 `i`칸 이동한 시점에서는 멤버 `j`가 팬 `i + j`와 마주 본다. 이 시점에 남성끼리 만난 쌍이 하나도 없으면 모든 멤버가 포옹한 것이다.

모든 시점을 하나씩 확인하면 된다.

```cpp
// members[j]는 멤버 j의 성별, fans[i + j]는 그 멤버가 만나는 팬의 성별이다.
int allHugCount(const string& members, const string& fans) {
    int hugCount = 0;
    int N = members.length();
    int M = fans.length();

    // 모든 멤버가 팬과 마주 보는 시점만 순회한다.
    for (int i = 0; i + N <= M; ++i) {
        bool ok = true;

        for (int j = 0; j < N; ++j) {
            // 남성 멤버가 남성 팬과 만나면 악수이므로 이 시점은 실패다.
            if (members[j] == 'M' && fans[i + j] == 'M') {
                ok = false;
                break;
            }
        }

        if (ok) ++hugCount;
    }

    return hugCount;
}
```

### 주의할 점

- **팬의 인덱스는 `fans[i + j]`다.** `fans[j]`로 쓰면 `i`와 무관하게 언제나 같은 구간만 검사하게 되어, 결과가 `0` 아니면 팬 수로 고정된다.
- **멤버의 성별도 함께 봐야 한다.** 악수는 남성 멤버와 남성 팬이 만날 때만 일어난다. 팬만 보고 `fans[i + j] == 'M'`으로 판정하면, 여성 멤버가 남성 팬과 포옹하는 경우까지 실패로 처리한다.
- **바깥 루프의 범위는 `i + N <= M`이다.** `i < M`으로 두면 멤버 일부가 팬과 마주 보지 못하는 시점까지 세고, `fans[i + j]`가 범위를 벗어난다.

### 시간복잡도

- 모든 멤버가 팬과 마주 보는 시점은 `M - N + 1`번이다.
- 각 시점마다 멤버 `N`명을 확인한다.

```text
시간복잡도: O((M - N + 1) × N) = O(NM)
```

`N`이 `M`의 절반쯤일 때 최악이 되어 연산 횟수가 약 `M² / 4`에 이른다. `M = 200,000`이면 한 케이스에만 약 `100억`번이고, 테스트 케이스가 최대 20개이므로 시간 제한 15초 안에는 들어올 수 없다.

문제의 정답은 구할 수 있지만 제한을 통과하지는 못하므로, 더 빠른 방법이 필요하다.

## 2. 곱셈으로의 변형

무식하게 풀기가 하는 일은 "시점마다 마주 본 쌍들을 모두 확인하는 것"이다. 그런데 이 계산은 사실 **곱셈이 하는 일과 똑같은 모양**이다.

### 2-1. 곱셈의 각 자리는 무엇을 더하는가

길이가 3인 정수 `A`와 길이가 6인 정수 `B`의 곱 `C`를 구하는 과정이다.

```text
                                          A2     A1     A0
x                    B5     B4     B3     B2     B1     B0
----------------------------------------------------------
                                       A2*B0  A1*B0  A0*B0
                                A2*B1  A1*B1  A0*B1
                         A2*B2  A1*B2  A0*B2
                  A2*B3  A1*B3  A0*B3
           A2*B4  A1*B4  A0*B4
    A2*B5  A1*B5  A0*B5
----------------------------------------------------------
     C7     C6     C5     C4     C3     C2     C1     C0
```

세로줄 하나가 결과의 한 자리다. 예를 들어 `C2`는 세 항을 더한다.

```text
C2 = A0*B2 + A1*B1 + A2*B0
```

일반화하면 다음과 같다.

```text
Ci = A0*Bi + A1*Bi-1 + A2*Bi-2
```

* 10진수가 아닌 21억 진수를 다루고 있다고 생각하면 편하다. 

### 2-2. 문제를 곱셈에 대응시키기

남성을 `1`, 여성을 `0`으로 두자. 그러면 두 값의 곱은 **둘 다 남성일 때만 `1`** 이 된다. 즉 곱 하나가 악수 한 번에 대응한다.

```text
M -> 1, F -> 0
1 * 1 = 1  (남남, 악수)
그 외      = 0  (포옹)
```

이제 첨자를 맞춰야 한다. 팬들이 `k`칸 이동한 시점에서는 멤버 `j`가 팬 `k + j`와 마주 보므로, 이 시점에 모이는 쌍들은 **두 첨자의 차가 `k`로 일정**하다. 반면 곱셈에서 한 자리에 모이는 항들은 **첨자의 합이 일정**했다.

차를 합으로 바꾸려면 한쪽을 뒤집으면 된다. 팬 배열을 뒤집어서 `B[M - 1 - i] = fans[i]`로 저장하면, 곱셈의 한 자리가 정확히 한 시점이 된다.

```cpp
for (int i = 0; i < N; ++i) A[i] = (members[i] == 'M');
for (int i = 0; i < M; ++i) B[M - i - 1] = (fans[i] == 'M');
```

이렇게 두면 `C[i]`는 **어떤 한 시점에 악수한 남남 쌍의 개수**가 된다. 따라서 `C[i] == 0`인 자리가 모든 멤버가 포옹한 시점이다.

모든 멤버가 팬과 마주 보는 시점만 세야 하는데, 뒤집은 첨자 기준으로 그 범위는 `i`가 `N - 1`부터 `M - 1`까지다. 개수는 `M - N + 1`로 앞서 센 것과 같다.

```cpp
int allHugs = 0;
for (int i = N - 1; i < M; ++i) {
    if (C[i] == 0) ++allHugs;
}
```

### 2-3. 자리 올림을 하면 안 된다

여기서 곱셈은 **수를 구하려는 것이 아니라 쌍의 개수를 세려는 것**이다. `C[i]`에는 남남 쌍의 개수가 그대로 남아 있어야 한다.

그런데 보통의 큰 수 곱셈은 각 자리를 `0`부터 `9` 사이로 맞추는 자리 올림(`normalize()`)을 한다. 이걸 그대로 쓰면 남남 쌍이 10쌍인 자리가 `0`이 되어버려서, `C[i] == 0` 판정이 "포옹"과 구별되지 않는다.

그래서 이 문제에서는 자리 올림을 생략한다. [karatsuba.cpp](karatsuba.cpp)의 `addTo()`, `subFrom()`, `multiply()`에서 `normalize()` 호출을 빼면 된다.

```cpp
// a += b * 10^k (자리 올림 없음)
void addTo(vector<int>& a, const vector<int>& b, int k) {
    if (a.size() < b.size() + k) a.resize(b.size() + k, 0);

    int bSize = static_cast<int>(b.size());
    for (int i = 0; i < bSize; ++i) {
        a[i + k] += b[i];
    }
}
```

곱셈 자체는 카라츠바 알고리즘을 그대로 쓴다. 구현과 설명은 [karatsuba.cpp](karatsuba.cpp)에 있다.

### 2-4. 전체 코드

```cpp
int hugs(const string& members, const string& fans) {
    int N = members.size(), M = fans.size();

    // 남성을 1, 여성을 0으로 둔다. 두 값의 곱이 1이면 남남 쌍, 즉 악수다.
    vector<int> A(N), B(M);
    for (int i = 0; i < N; ++i) A[i] = (members[i] == 'M');

    // 팬은 뒤집어서 저장한다. 그래야 곱셈의 각 자리가 한 시점과 대응된다.
    for (int i = 0; i < M; ++i) B[M - i - 1] = (fans[i] == 'M');

    // C[i]는 해당 시점에 악수한 남남 쌍의 수가 된다.
    vector<int> C = karatsuba(A, B);

    // 모든 멤버가 팬과 마주 보는 시점은 i가 N - 1부터 M - 1까지다.
    int allHugs = 0;
    for (int i = N - 1; i < M; ++i) {
        if (C[i] == 0) ++allHugs;
    }
    return allHugs;
}
```

### 시간복잡도

팬 수 `M`을 `n`이라고 하면, 배열을 만드는 과정은 `O(n)`이고 결과를 세는 과정도 `O(n)`이다. 전체 비용은 곱셈이 지배한다.

```text
시간복잡도: O(n^log2(3)) = O(n^1.585)
```

무식하게 풀기의 `O(NM)`이 최악에 약 `100억`번이었던 것과 비교하면 충분히 줄어든다.
