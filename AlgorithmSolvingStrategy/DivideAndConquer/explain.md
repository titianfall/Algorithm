# 분할 정복: Divide and Conquer

> 큰 문제를 같은 형태의 작은 문제로 나눈 뒤,  
> 각 부분 문제의 답을 합쳐 전체 문제의 답을 구하는 방법이다.

분할 정복은 완전 탐색이나 단순 재귀와 마찬가지로 재귀 호출을 자주 사용한다.  
하지만 핵심은 단순히 “자기 자신을 다시 호출한다”가 아니라, **문제를 더 작은 조각으로 나누고 다시 합치는 구조**에 있다.

# 1. 개념

## 1.1 분할 정복이란?

분할 정복은 보통 세 단계로 이루어진다.

1. **분할 divide**  
   현재 문제를 둘 이상의 더 작은 부분 문제로 나눈다.

2. **정복 conquer**  
   나누어진 부분 문제를 각각 푼다. 부분 문제가 여전히 크다면 같은 방식으로 다시 나눈다.

3. **병합 merge**  
   부분 문제들의 답을 합쳐 원래 문제의 답을 만든다.

재귀 호출과의 차이를 감각적으로 보면 다음과 같다.

```text
일반 재귀:
문제 하나를 조금 줄인 문제 하나로 바꾼다.

예: sum(n) = sum(n - 1) + n

분할 정복:
문제를 비슷한 크기의 여러 부분 문제로 나눈다.

예: fastSum(n) = fastSum(n / 2) + fastSum(n / 2) + 추가 계산
```

즉, 분할 정복은 문제의 크기를 빠르게 줄일 수 있을 때 강력하다.

## 1.2 기본 구조

중요한 질문은 세 가지이다.

- 문제를 어떻게 나눌 수 있는가?
- 더 이상 나누지 않아도 되는 기저 사례는 무엇인가?
- 부분 문제의 답을 어떻게 합쳐야 전체 답이 되는가?

## 1.3 1부터 n까지의 합

먼저 단순 재귀로 `1 + 2 + ... + n`을 구해 보자.

```cpp
int recursiveSum(int n) {
    if (n == 1) return 1;
    return recursiveSum(n - 1) + n;
}
```

이 코드는 한 번 호출될 때마다 문제 크기가 `1`씩만 줄어든다.

```text
recursiveSum(10)
= recursiveSum(9) + 10
= recursiveSum(8) + 9 + 10
= ...
= recursiveSum(1) + 2 + ... + 10
```

따라서 시간복잡도는 `O(n)`이다.

## 1.4 빠른 합 fastSum

같은 문제를 분할 정복으로 생각하면 `1 + 2 + ... + n`을 절반으로 나눌 수 있다.

```text
1 + 2 + ... + n
= (1 + 2 + ... + n/2)
  + (n/2 + 1 + n/2 + 2 + ... + n)
```

첫 번째 절반은 그대로 `fastSum(n / 2)`이다.

두 번째 절반은 모양을 바꾸면 다음과 같다.

```text
(n/2 + 1) + (n/2 + 2) + ... + (n/2 + n/2)
= (1 + 2 + ... + n/2) + (n/2) * (n/2)
= fastSum(n / 2) + (n / 2) * (n / 2)
```

그래서 `n`이 짝수일 때는 다음 식을 얻을 수 있다.

```text
fastSum(n) = 2 * fastSum(n / 2) + (n / 2) * (n / 2)
```

C++ 코드로 쓰면 다음과 같다.

```cpp
int fastSum(int n) {
    if (n == 1) return 1;
    if (n % 2 == 1) return fastSum(n - 1) + n;

    return 2 * fastSum(n / 2) + (n / 2) * (n / 2);
}
```

홀수일 때는 먼저 `n - 1`로 만들어 짝수 문제로 바꾼다.

```text
fastSum(1011)
= fastSum(1010) + 1011
= 2 * fastSum(505) + 505 * 505 + 1011
```

중간에 홀수가 나오면 한 번 줄이고, 짝수가 되면 다시 절반으로 나눈다.  
문제 크기가 계속 절반에 가깝게 줄어들기 때문에 전체 시간복잡도는 `O(log n)`으로 볼 수 있다.

## 1.5 행렬의 빠른 거듭제곱

`n x n` 정방 행렬 `A`가 있을 때, `A^m`을 단순하게 구하면 행렬 곱셈을 `m`번 반복해야 한다.

```text
A^m = A * A * A * ... * A
```

행렬 곱셈 한 번이 `O(n^3)`이라면, 단순 반복 방식은 `O(n^3 * m)`이 된다.  
예를 들어 `m = 1,000,000`처럼 커지면 너무 느리다.

분할 정복을 사용하면 다음 성질을 이용할 수 있다.

```text
A^m = A^(m/2) * A^(m/2)          // m이 짝수일 때
A^m = A^(m-1) * A                // m이 홀수일 때
```

```cpp
// 정방 행렬을 표현하는 SquareMatrix 클래스가 있다고 가정한다.
class SquareMatrix;

// n x n 크기의 항등 행렬을 반환한다.
SquareMatrix identity(int n);

// A^m을 반환한다.
SquareMatrix pow(const SquareMatrix& A, int m) {
    if (m == 0) return identity(A.size());
    if (m % 2 == 1) return pow(A, m - 1) * A;

    SquareMatrix half = pow(A, m / 2);
    return half * half;
}
```

이 방식은 지수를 계속 절반으로 줄이므로 행렬 곱셈 횟수가 `O(log m)`번으로 줄어든다.  
따라서 전체 시간복잡도는 `O(n^3 log m)`이다.

## 1.6 홀수 지수를 어떻게 나눌까?

`A^7`을 구할 때 다음처럼 생각할 수도 있다.

```text
A^7 = A^3 * A^4
```

겉보기에는 `A * A^6`보다 더 균형 있게 나눈 것처럼 보인다.  
하지만 실제로는 더 느려질 수 있다.

왜냐하면 `A^3`과 `A^4`를 각각 따로 계산하면서 같은 부분 문제가 다시 등장하기 때문이다.

```text
나쁜 방향:
pow(A, 31)
├─ pow(A, 15) > pow(A, 7) * pow(A, 8) (중복 계산)
└─ pow(A, 16)
   └─ pow(A, 8)
      └─ pow(A, 4)
         └─ pow(A, 2)
            └─ pow(A, 1)
```

반면 위의 코드처럼 홀수일 때 `1`을 먼저 빼면 한 줄로 이어진다.

```text
좋은 방향:
pow(A, 31)
-> pow(A, 30)
-> pow(A, 15)
-> pow(A, 14)
-> pow(A, 7)
-> pow(A, 6)
-> pow(A, 3)
-> pow(A, 2)
-> pow(A, 1)
```

이처럼 같은 부분 문제가 여러 번 등장하는 성질을 **중복 부분 문제 overlapping subproblems**라고 한다.  
중복 부분 문제가 많아지면 단순 분할 정복만으로는 느려질 수 있고, 이때는 동적 계획법이나 메모이제이션을 함께 고려한다.

## 1.7 병합 정렬과 퀵 정렬

병합 정렬과 퀵 정렬은 둘 다 분할 정복의 대표적인 예이다.  
차이는 시간을 어디에 더 쓰는지에 있다.

### 병합 정렬

병합 정렬은 배열을 절반으로 나누는 작업은 쉽다.

```text
[8, 3, 5, 1, 2, 7]
-> [8, 3, 5] + [1, 2, 7]
```

대신 정렬된 두 배열을 다시 합치는 병합 과정에서 `O(n)` 시간이 든다.

```text
분할: O(1)에 가깝다.
병합: 각 단계마다 O(n)이 든다.
단계 수: O(log n)

전체 시간복잡도: O(n log n)
```

단순한 병합 정렬 구현은 [mergeSort.cpp](<mergeSort.cpp>)에 정리했다.  
이 코드는 배열을 계속 반으로 나눈 뒤, 정렬된 두 구간을 `temp` 배열에 합치고 다시 원래 배열로 복사한다.

### 퀵 정렬

퀵 정렬은 기준 원소 pivot을 고르고, pivot보다 작은 값과 큰 값으로 배열을 나눈다.

```text
[8, 3, 5, 1, 2, 7], pivot = 5
-> [3, 1, 2] + [5] + [8, 7]
```

퀵 정렬은 병합 과정이 거의 필요 없지만, 분할 과정에서 원소들을 pivot 기준으로 재배치해야 한다.  
또 pivot을 어떻게 고르느냐에 따라 성능이 크게 달라진다.

```text
평균 시간복잡도: O(n log n)
최악 시간복잡도: O(n^2)
```

가능한 한 절반에 가까운 분할을 얻기 위해 좋은 pivot을 고르는 것이 중요하다.

단순한 퀵 정렬 구현은 [quickSort.cpp](<quickSort.cpp>)에 정리했다.  
이 코드는 왼쪽에서 pivot 이상인 값, 오른쪽에서 pivot 이하인 값을 찾은 뒤 두 값을 교환하는 방식으로 구간을 나눈다.

### C++ 표준 라이브러리 정렬 함수

- `std::sort`: 일반적인 전체 정렬 함수이다. 보통 퀵 정렬 기반으로 시작하고, 상황이 나빠지면 힙 정렬로 전환하며, 작은 구간은 삽입 정렬로 처리하는 **introsort** 계열로 구현된다.
- `std::stable_sort`: 같은 값들의 기존 순서를 유지하는 안정 정렬이다. 구현체에 따라 병합 정렬 계열의 방식을 사용한다.
- `std::merge`: 이미 정렬된 두 구간을 하나로 합치는 함수이다. 병합 정렬 전체가 아니라, 병합 정렬의 **merge 단계**에 해당한다.

코테에서는 보통 전체 정렬이 필요하면 `std::sort`를 쓰고, 안정성이 필요하면 `std::stable_sort`를 쓴다.  
이미 정렬된 두 배열을 합칠 때만 `std::merge`를 사용한다.

큰 수 곱셈 예제 코드는 [bigDecimal.cpp](<bigDecimal.cpp>)에 있다.  
이 파일의 `normalize()` 함수는 각 칸에 쌓인 값을 실제 십진수 자릿수처럼 정리한다.

코드에서는 숫자를 다음처럼 **1의 자리부터 거꾸로** 저장한다.

```cpp
vector<int> a = {3, 2, 1}; // 123
vector<int> b = {6, 5, 4}; // 456
```

따라서 `a[0]`은 1의 자리, `a[1]`은 10의 자리, `a[2]`는 100의 자리이다.

곱셈할 때는 일단 올림을 생각하지 않고 같은 자리끼리 모두 더한다.

```cpp
c[i + j] += a[i] * b[j];
```

`123 * 456`을 계산하면 `normalize()`를 부르기 전 배열은 대략 다음처럼 된다.

```text
c[0] = 3 * 6                  = 18
c[1] = 3 * 5 + 2 * 6          = 27
c[2] = 3 * 4 + 2 * 5 + 1 * 6  = 28
c[3] = 2 * 4 + 1 * 5          = 13
c[4] = 1 * 4                  = 4

정리 전: [18, 27, 28, 13, 4]
```

하지만 한 자릿수에는 `0`부터 `9`까지만 들어갈 수 있다.  
그래서 `10` 이상인 값은 다음 칸으로 넘겨야 한다.

```text
[18, 27, 28, 13, 4]

i = 0:
18은 8만 남기고 1을 다음 자리로 넘긴다.
=> [8, 28, 28, 13, 4]

i = 1:
28은 8만 남기고 2를 다음 자리로 넘긴다.
=> [8, 8, 30, 13, 4]

i = 2:
30은 0만 남기고 3을 다음 자리로 넘긴다.
=> [8, 8, 0, 16, 4]

i = 3:
16은 6만 남기고 1을 다음 자리로 넘긴다.
=> [8, 8, 0, 6, 5]
```

배열은 1의 자리부터 저장되어 있으므로 거꾸로 출력하면 실제 값이 된다.

```text
[8, 8, 0, 6, 5]
=> 56088
```

즉 `normalize()`의 핵심은 다음 두 줄이다.

```cpp
num[i + 1] += num[i] / 10; // 몫은 다음 자리로 올림
num[i] %= 10;              // 현재 자리에는 나머지만 남김
```

손으로 계산할 때 `18`을 쓰면서 `8`을 적고 `1`을 올리는 것과 같은 원리이다.

## 2.2 카라츠바 곱셈

<details>
<summary>펼쳐 보기</summary>

<br>

카라츠바 곱셈 구현은 [karatsuba.cpp](<karatsuba.cpp>)에 정리했다.  
이 코드는 큰 수를 두 부분으로 나눈 뒤, 곱셈 횟수를 줄여서 더 빠르게 계산한다.

일반적인 큰 수 곱셈은 모든 자릿수 쌍을 곱한다.

```text
a의 각 자리 n개 * b의 각 자리 n개
=> O(n^2)
```

카라츠바는 수를 아래쪽 절반과 위쪽 절반으로 나눈다.

```text
a = a1 * 10^half + a0
b = b1 * 10^half + b0
```

원래대로라면 다음 네 번의 곱셈이 필요하다.

```text
a0 * b0
a0 * b1
a1 * b0
a1 * b1
```

하지만 카라츠바는 세 번의 곱셈만 사용한다.

```text
z0 = a0 * b0
z2 = a1 * b1
z1 = (a0 + a1) * (b0 + b1) - z0 - z2
```

여기서 `z1`은 실제로 다음 값을 의미한다.

```text
z1 = a0 * b1 + a1 * b0
```

따라서 최종 결과는 다음처럼 합친다.

```text
result = z0 + z1 * 10^half + z2 * 10^(2 * half)
```

### 시간복잡도

단순 곱셈은 크기 `n`인 두 수를 곱할 때 `n * n`개의 자릿수 곱셈을 하므로 `O(n^2)`이다.

카라츠바는 크기 `n` 문제를 크기 `n/2`짜리 곱셈 3개로 줄인다.  
나머지 덧셈, 뺄셈, 자릿수 올림은 각 단계에서 대략 `O(n)` 시간이 든다.

```text
T(n) = 3T(n/2) + O(n)
```

이 점화식을 풀면 다음과 같다.

```text
T(n) = O(n^log2(3))
     ≈ O(n^1.585)
```

그래서 카라츠바는 이론적으로 단순 곱셈 `O(n^2)`보다 빠르다.  
다만 작은 입력에서는 재귀 호출과 벡터 복사 비용이 더 커질 수 있으므로, 코드에서는 일정 크기 이하일 때 단순 곱셈으로 바꾼다.

```cpp
if(an <= 50 || bn <= 50) return multiply(a, b);
```

## 2.3 쿼드 트리 뒤집기 (QUADTREE)

<details>
<summary>펼쳐 보기</summary>

<br>

- 문제: [Algospot QUADTREE](https://algospot.com/judge/problem/read/QUADTREE)
- 학습 노트: [quadtree.md](<quadtree.md>) · 구현: [quadTree.cpp](<quadTree.cpp>)

흑백 그림을 압축한 쿼드 트리 문자열을 **상하로 뒤집은 결과**로 다시 출력하는 문제다.

```text
노드 = b | w | x + 노드 4개
```

`x`의 자식은 항상 `왼쪽 위(UL)`, `오른쪽 위(UR)`, `왼쪽 아래(LL)`, `오른쪽 아래(LR)` 순서다.  
상하 반전은 위쪽 두 조각과 아래쪽 두 조각의 자리를 바꾸는 것과 같다.

```text
x + UL + UR + LL + LR
↓
x + LL + LR + UL + UR
```

### 핵심 아이디어: 그림을 만들지 않는다

원본 그림이 최대 `2^20 × 2^20`이므로 실제 배열로 펼치면 `O(S^2)` 메모리가 필요해 제한을 넘는다.  
대신 **압축 문자열을 파싱하면서 바로 뒤집은 문자열을 반환**하면 된다.

```cpp
// 현재 노드를 뒤집은 쿼드 트리 문자열로 반환한다.
string reverse(string::iterator& it) {
    // 현재 노드를 읽고, 다음 문자로 반복자를 옮긴다.
    char head = *(it++);

    // 기저 사례: 한 색으로만 이루어진 영역은 뒤집어도 같다.
    if(head == 'b' || head == 'w') {
        return string(1, head);
    }

    // x이면 네 사분면을 원래 순서대로 끝까지 읽는다.
    string upperLeft = reverse(it);
    string upperRight = reverse(it);
    string lowerLeft = reverse(it);
    string lowerRight = reverse(it);

    // 각각 위와 아래 조각들의 위치를 바꾼다.
    return "x" + lowerLeft + lowerRight + upperLeft + upperRight;
}
```

반복자를 **참조로** 넘기는 것이 핵심이다. 재귀 호출 전체에서 앞으로만 이동하므로 각 문자를 정확히 한 번만 읽는다.

### 시간복잡도

| 방법 | 시간복잡도 |
| --- | --- |
| `substr()`로 사분면을 잘라 재귀 | `O(nh)` — 균형 트리면 `O(n log n)`, 최악 `O(n^2)` |
| 반복자로 한 번에 파싱 | `O(n)`, 추가 메모리 `O(h)` |

자세한 설명과 `getLength()` / `decompress()` 방식 비교는 [quadtree.md](<quadtree.md>)에 있다.

## 2.4 울타리 잘라내기 (FENCE)

<details>
<summary>펼쳐 보기</summary>

<br>

- 문제: [Algospot FENCE](https://algospot.com/judge/problem/read/FENCE)
- 학습 노트: [fence.md](<fence.md>) · 구현: [fence.cpp](<fence.cpp>)

너비가 `1`인 판자 `N`개가 늘어서 있을 때, 잘라낼 수 있는 직사각형의 **최대 넓이**를 구한다.  
넓이는 `선택한 판자 수 × 구간의 최소 높이`이므로, 각 구간에서 **가장 낮은 판자가 높이를 결정**한다.

### 분할: 세 가지 경우뿐이다

구간 `[left, right]`의 중간을 `mid`라 하면 최대 직사각형은 반드시 셋 중 하나다.

1. 왼쪽 `[left, mid]`에만 존재한다. → 재귀
2. 오른쪽 `[mid + 1, right]`에만 존재한다. → 재귀
3. `mid`와 `mid + 1`을 모두 포함한다. → 직접 계산

세 번째는 `[mid, mid + 1]`에서 시작해 한 칸씩 확장한다. **양쪽 모두 가능하면 다음 판자가 더 높은 쪽을 먼저 포함한다.**

```cpp
// 부분문제 3: 중앙을 가로지르는 직사각형은 mid와 mid + 1을 모두 포함한다.
int lo = mid;
int hi = mid + 1;
int minHeight = min(h[lo], h[hi]);
maxArea = max(maxArea, minHeight * 2);

while (lo > left || hi < right) {
    // 양쪽 모두 가능하면 다음 판자가 더 높은 쪽을 먼저 확장한다.
    if (hi < right && (lo == left || h[lo - 1] < h[hi + 1])) {
        ++hi;
        minHeight = min(minHeight, h[hi]);
    } else {
        --lo;
        minHeight = min(minHeight, h[lo]);
    }

    maxArea = max(maxArea, minHeight * (hi - lo + 1));
}
```

### 합치기가 `O(N)`인 이유

`lo`는 왼쪽으로만, `hi`는 오른쪽으로만 움직이며 되돌아오지 않는다. 그리고 최소 높이를 매번 다시 훑지 않고 **새로 들어온 판자 하나와만 비교**해 갱신하므로 루프 한 번이 `O(1)`이다.

```cpp
minHeight = min(minHeight, h[hi]);  // 새 판자 하나와만 비교
```

```text
T(N) = 2T(N / 2) + O(N)
     = O(N log N)
```

### 무식하게 풀기와의 비교

`N = 20,000`, 테스트 케이스 50개인 최악의 입력에서:

| 방법 | 케이스당 연산 | 전체 (50 케이스) |
| --- | --- | --- |
| 무식하게 풀기 `O(N²)` | 약 4억 | 약 200억 |
| 분할 정복 `O(N log N)` | 약 30만 | 약 1,500만 |

귀류법을 통한 부분문제 3의 증명과 재귀 트리 분석은 [fence.md](<fence.md>)에 있다.

</details>

## 2.5 팬 미팅 (FANMEETING)

<details>
<summary>펼쳐 보기</summary>

<br>

- 문제: [Algospot FANMEETING](https://algospot.com/judge/problem/read/FANMEETING)
- 학습 노트: [fanmeeting.md](<fanmeeting.md>) · 구현: [fanmeeting.cpp](<fanmeeting.cpp>)

멤버들과 팬들이 한 칸씩 이동하며 인사할 때, **모든 멤버가 동시에 포옹하는 시점의 수**를 센다.  
남성 멤버와 남성 팬이 만날 때만 악수이고, 나머지는 모두 포옹이다.

무식하게 풀면 각 시점마다 멤버 `N`명을 확인하므로 `O(NM)`이고, `M = 200,000`일 때 한 케이스에만 약 `100억`번이라 통과할 수 없다.

### 핵심 아이디어: 이 문제는 곱셈이다

남성을 `1`, 여성을 `0`으로 두면 **두 값의 곱은 둘 다 남성일 때만 `1`** 이다. 즉 곱 하나가 악수 한 번이다.

곱셈에서 결과의 한 자리에 모이는 항들은 **첨자의 합이 일정**하다.

```text
Ci = A0*Bi + A1*Bi-1 + A2*Bi-2
```

반면 이 문제에서 한 시점에 모이는 쌍들은 **첨자의 차가 일정**하다. 차를 합으로 바꾸려면 **한쪽을 뒤집으면** 된다.

```cpp
int hugs(const string& members, const string& fans) {
    int N = members.size(), M = fans.size();

    // 남성을 1, 여성을 0으로 둔다. 두 값의 곱이 1이면 남남 쌍, 즉 악수다.
    vector<int> A(N), B(M);
    for (int i = 0; i < N; ++i) A[i] = (members[i] == 'M');

    // 팬은 뒤집어서 저장한다. 그래야 곱셈의 각 자리가 한 시점과 대응된다.
    for (int i = 0; i < M; ++i) B[M - i - 1] = (fans[i] == 'M');

    // C[i]는 해당 시점에 악수한 남남 쌍의 수가 된다.
    vector<int> C = karatsuba(A, B);

    // 모든 멤버가 팬과 마주 보는 시점은 i가 N - 1부터 M - 1까지다.
    int allHugs = 0;
    for (int i = N - 1; i < M; ++i) {
        if (C[i] == 0) ++allHugs;
    }
    return allHugs;
}
```

### 자리 올림을 하면 안 된다

여기서 곱셈은 수를 구하려는 것이 아니라 **쌍의 개수를 세려는 것**이다. `normalize()`를 그대로 쓰면 남남 쌍이 10쌍인 자리가 `0`이 되어 포옹과 구별되지 않는다. 그래서 [카라츠바 곱셈](#22-카라츠바-곱셈)에서 `normalize()` 호출만 빼고 쓴다.

### 시간복잡도

배열을 만들고 결과를 세는 과정은 `O(n)`이므로 전체 비용은 곱셈이 지배한다.

```text
시간복잡도: O(n^log2(3)) = O(n^1.585)
```

</details>
