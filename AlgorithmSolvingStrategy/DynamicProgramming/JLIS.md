# 합친 LIS: JLIS

> 두 수열에서 각각 부분 수열을 고른 뒤 하나의 증가 수열로 합쳤을 때, 만들 수 있는 가장 긴 길이를 구하는 동적 계획법 문제다.

- 문제 ID: `JLIS`
- 출처: [알고스팟 - 합친 LIS](https://algospot.com/judge/problem/read/JLIS)
- 시간 제한: 2초
- 메모리 제한: 64MB

## 문제 설명

수열에서 원소를 0개 이상 지우되 남은 원소의 순서를 유지해서 만든 수열을 **부분 수열**이라고 한다.

예를 들어 다음 수열이 있을 때,

```text
4 3 7 6 9
```

`4 7 6`, `3 6 9` 등은 원래 순서를 지킨 부분 수열이다. 이 가운데 모든 원소가 앞의 원소보다 큰 부분 수열을 **증가 부분 수열**이라고 한다.

이제 두 정수 수열 `A`, `B`에서 각각 증가 부분 수열을 하나씩 고른다. 한쪽에서는 원소를 하나도 고르지 않아도 된다. 두 부분 수열의 원소를 오름차순으로 합쳐 만든 수열을 **합친 증가 부분 수열**이라고 한다. 이 중 가장 긴 수열이 **JLIS(Joined Longest Increasing Subsequence)**다.

예를 들어 다음 두 수열을 보자.

```text
A = 1 9 4
B = 3 4 7
```

`A`에서는 `1 9`, `B`에서는 `3 4 7`을 고를 수 있다. 두 부분 수열을 값의 크기순으로 합치면 다음과 같다.

```text
1 3 4 7 9
```

따라서 이 경우 길이 `5`인 합친 증가 부분 수열을 만들 수 있다.

두 수열 `A`, `B`가 주어질 때 만들 수 있는 JLIS의 최대 길이를 구하라.

## 입력

입력의 첫 줄에는 테스트 케이스의 수 `C`가 주어진다.

각 테스트 케이스는 세 줄로 구성된다.

1. 첫 줄에 수열 `A`와 `B`의 길이 `n`, `m`이 주어진다.
2. 다음 줄에 `A`의 원소 `n`개가 주어진다.
3. 그다음 줄에 `B`의 원소 `m`개가 주어진다.

## 출력

각 테스트 케이스마다 한 줄에 JLIS의 최대 길이를 출력한다.

## 예제

**입력**

```text
3
3 3
1 2 4
3 4 7
3 3
1 2 3
4 5 6
5 3
10 20 30 1 2
10 20 30
```

**출력**

```text
5
6
5
```

## 제한

| 항목 | 제한 |
| --- | --- |
| 시간 제한 | 2초 (`2000ms`) |
| 메모리 제한 | 64MB (`65536KB`) |
| 테스트 케이스 수 `C` | 1 이상 50 이하 |
| 수열 `A`의 길이 `n` | 1 이상 100 이하 |
| 수열 `B`의 길이 `m` | 1 이상 100 이하 |
| 각 원소 | 32비트 부호 있는 정수 |

## 문제를 이해할 때 주의할 점

### 두 원본 수열의 순서는 각각 유지한다

`A`에서 고른 원소끼리의 순서와 `B`에서 고른 원소끼리의 순서는 바꿀 수 없다. 다만 두 수열에서 고른 원소들을 서로 섞는 순서는 전체 결과가 증가하도록 정할 수 있다.

### 같은 값을 두 번 넣을 수 없다

JLIS도 모든 원소가 이전 원소보다 **엄격하게 커야 하는** 증가 수열이다. 따라서 `A`와 `B`에서 같은 값을 골랐더라도 결과 수열에는 그 값을 두 번 연속 넣을 수 없다.

### 두 수열을 단순히 이어 붙이는 문제가 아니다

`A` 뒤에 `B`를 붙인 하나의 배열에서 LIS를 구하면 두 수열 사이의 선택 순서까지 강제로 고정된다. JLIS에서는 `A`와 `B`에서 선택한 원소를 값의 크기에 맞게 교차해서 배치할 수 있으므로 서로 다른 문제다.

### 각 수열의 LIS를 따로 구해 더해도 안 된다

각 수열에서 독립적으로 고른 LIS가 서로 같은 값을 포함하거나, 두 결과를 합쳤을 때 가장 긴 증가 수열이 되지 않을 수 있다. 두 수열에서 다음 원소를 고르는 선택을 함께 고려해야 한다.

## 풀이

### 두 수열의 LIS를 각각 구해서 합치면 안 된다

이 문제는 앞에서 풀었던 LIS 문제의 확장판이다. 본질적인 접근은 LIS 문제와 크게 다르지 않다.

처음에는 두 수열의 LIS를 각각 찾은 뒤, 두 결과를 합치면 되지 않을까 생각할 수 있다. 그러나 이 방법으로는 문제를 해결할 수 없다.

세 번째 예제의 JLIS를 만들려면 첫 번째 수열에서 `1, 2`를 선택하고, 두 번째 수열에서 `10, 20, 30`을 선택해야 하기 때문이다. 각 수열의 LIS를 독립적으로 구하면 이러한 조합을 찾을 수 없다.

### LIS에서 사용한 재귀 함수 확장하기

수열 `S`의 최대 증가 부분 수열을 찾는 재귀 함수 `lis3()`의 정의는 다음과 같았다.

```text
lis3(start) = S[start]에서 시작하는 최대 증가 부분 수열의 길이
```

이제 수열이 `A`, `B` 두 개로 늘었으므로 재귀 함수도 두 개의 인덱스를 입력으로 받아야 한다. 다음과 같은 형태의 재귀 함수로 문제를 풀 수 있는지 생각해 보자.

```text
jlis(indexA, indexB)
    = A[indexA]와 B[indexB]에서 시작하는
      합친 증가 부분 수열의 최대 길이
```

두 수의 순서는 지정하지 않았으므로 `A[indexA]`와 `B[indexB]` 중 작은 값이 앞에 온다고 하자.

그러면 다음에 선택할 수 있는 숫자는 다음 두 경우 중 하나다.

- `A`에서 `indexA`보다 뒤에 있으면서 `max(A[indexA], B[indexB])`보다 큰 원소
- `B`에서 `indexB`보다 뒤에 있으면서 `max(A[indexA], B[indexB])`보다 큰 원소

`A[nextA]`를 다음 숫자로 선택하면 길이에 `1`을 더하고 `jlis(nextA, indexB)`를 호출한다. `B[nextB]`를 선택한 경우도 같은 방식으로 처리한다.

점화식을 의사 코드로 표현하면 다음과 같다.

```text
jlis(indexA, indexB) = max(
        jlis(nextA, indexB) + 1,
        jlis(indexA, nextB) + 1
      )
```

여기서 `nextA`와 `nextB`는 각각 증가 부분 수열의 다음 위치로 선택할 수 있는 `A`, `B` 원소의 인덱스다.

이 아이디어를 코드로 구현해 보자.

### 합친 LIS를 구하는 동적 계획법

아래 코드에서 가상의 작은 값을 표현하기 위해 64비트 정수인 `NEGINF`를 사용한 점을 눈여겨보자. 문제의 입력은 32비트 부호 있는 정수 전체를 사용할 수 있으므로, 입력에 절대로 등장하지 않는 더 작은 값을 만들려면 64비트 정수가 필요하다.

```cpp
// 입력이 32비트 부호 있는 정수의 모든 값을 가질 수 있으므로
// 인위적인 최솟값은 64비트여야 한다.
const long long NEGINF = numeric_limits<long long>::min();

int n, m, A[100], B[100];
int cache[101][101];

// min(A[indexA], B[indexB]), max(A[indexA], B[indexB])로 시작하는
// 합친 증가 부분 수열의 최대 길이를 반환한다.
// 단, indexA == indexB == -1 혹은 A[indexA] != B[indexB]라고 가정한다.
int jlis(int indexA, int indexB) {
    // 메모이제이션
    int& ret = cache[indexA + 1][indexB + 1];
    if(ret != -1) return ret;

    // A[indexA], B[indexB]가 이미 존재하므로 2개는 항상 있다.
    ret = 2;
    long long a = (indexA == -1 ? NEGINF : A[indexA]);
    long long b = (indexB == -1 ? NEGINF : B[indexB]);

    long long maxElement = max(a, b);

    // 다음 원소를 찾는다.
    /**
     * ret: 지금까지 찾은 JLIS의 최대 길이
     * jlis(nextA, indexB): A[nextA]를 선택한 이후 만들 수 있는 JLIS의 최대 길이
     * + 1 : 이번에 A[nextA]를 선택한 것 한 개
     * 
     * jlis(indexA, nextB): B[nextB]를 선택한 이후 만들 수 있는 JLIS의 최대 길이
     */
    for(int nextA = indexA + 1; nextA < n; ++nextA) {
        if(maxElement < A[nextA]) {
            
            ret = max(ret, jlis(nextA, indexB) + 1);
        }
    }

    for(int nextB = indexB + 1; nextB < m; ++ nextB) {
        if(maxElement < B[nextB]) {
            ret = max(ret, jlis(indexA, nextB) + 1);
        }
    }
    
    return ret;
}
```

이 코드를 앞에서 사용한 LIS의 `lis3()`와 비교해 보면, 수열과 인덱스가 하나씩 늘어났을 뿐 전체적인 재귀 구조는 매우 비슷하다는 것을 알 수 있다.
