# 타일링 방법의 수 세기: TILING2

> `2 × n` 직사각형을 `2 × 1` 타일로 빈틈없이 덮는 방법의 수를 세는 문제다. 최적화가 아니라 **경우의 수**를 세는 동적 계획법의 가장 기본적인 예제다.

## 문제 설명

`2 × n` 크기의 사각형을 `2 × 1` 크기의 사각형으로 빈틈없이 채우는 경우의 수를 구하는 프로그램을 작성하라.

예를 들어 `n = 5`라고 하면 다음 그림과 같이 여덟 가지의 방법이 있다.

```text
n = 5 → 8가지

┌─┬─┬─┬─┬─┐   ┌─┬─┬─┬───┐   ┌─┬─┬───┬─┐   ┌─┬───┬─┬─┐
│ │ │ │ │ │   │ │ │ ├───┤   │ │ ├───┤ │   │ ├───┤ │ │
└─┴─┴─┴─┴─┘   └─┴─┴─┴───┘   └─┴─┴───┴─┘   └─┴───┴─┴─┘

┌───┬─┬─┬─┐   ┌───┬───┬─┐   ┌───┬─┬───┐   ┌─┬───┬───┐
├───┤ │ │ │   ├───┼───┤ │   ├───┤ ├───┤   │ ├───┼───┤
└───┴─┴─┴─┘   └───┴───┴─┘   └───┴─┴───┘   └─┴───┴───┘
```

경우의 수는 `n`이 커지면 아주 커질 수 있으므로, `1000000007`으로 나눈 값을 대신 출력한다.

## 입력

입력의 첫 줄에는 테스트 케이스의 수 `C(C ≤ 50)`가 주어진다.

그 후 `C`줄에 각각 1개의 자연수로 `n(1 ≤ n ≤ 100)`이 주어진다.

## 출력

각 테스트 케이스마다 한 줄에 경우의 수를 `1000000007`으로 나눈 나머지를 출력한다.

## 제한

| 항목 | 제한 |
| --- | --- |
| 시간 제한 | 1초 (1,000ms) |
| 메모리 제한 | 64MB (65,536KB) |
| 테스트 케이스 수 `C` | 50 이하 |
| 사각형의 너비 `n` | 1 이상 100 이하 |
| 나머지 연산의 법 `MOD` | 1,000,000,007 |

## 예제

**입력**

```text
3
1
5
100
```

**출력**

```text
1
8
782204094
```

`tiling(n) = F(n + 1)`이므로 `tiling(1) = F(2) = 1`, `tiling(5) = F(6) = 8`이다. `tiling(100) = F(101)`은 21자리 수라 64비트 정수로도 담을 수 없고, `1000000007`로 나눈 나머지가 `782204094`다.

## 접근

### 완전 탐색부터 시작하기

경우의 수를 세는 문제도 최적화 문제와 똑같이 **완전 탐색**에서 출발한다. 먼저 모든 답을 만들어 보는 함수를 작성한 뒤, 각 답을 세는 대신 개수만 반환하도록 바꾸면 된다.

```text
tiling(n) = 2 × n 크기의 사각형을 타일로 덮는 방법의 수
```

문제는 "타일을 어떤 순서로 놓을지"를 그대로 조각으로 삼으면 같은 타일링을 여러 번 세게 된다는 것이다. 타일 세 개를 놓는 순서만 바꿔도 결과가 같은 타일링이 되기 때문이다.

### 답을 유일하게 만드는 기준 정하기

같은 답을 두 번 세지 않으려면, **답을 만드는 과정이 유일하게 결정되어야** 한다. 여기서는 "맨 왼쪽 세로줄을 어떻게 채우는가"를 기준으로 삼는다.

빈 `2 × n` 사각형의 맨 왼쪽 세로줄은 반드시 어떤 타일로든 덮여야 하고, 가능한 모양은 두 가지뿐이다.

1. 세로 타일 한 개로 왼쪽 한 칸짜리 세로줄을 덮는다 → 남는 부분은 `2 × (n - 1)`
2. 가로 타일 두 개를 위아래로 겹쳐 놓아 왼쪽 두 칸을 덮는다 → 남는 부분은 `2 × (n - 2)`

```text
   ┌─┐               ┌───┐
   │ │  2 × (n-1)    ├───┤  2 × (n-2)
   └─┘               └───┘
   (1)                 (2)
```

이 두 가지 분류가 답이 되려면 다음 두 조건을 모두 만족해야 한다.

- **완전성**: 이 두 가지 분류는 가능한 타일링 방법을 **모두** 포함한다.
- **배타성**: 두 가지 분류에 **모두** 포함되는 타일링 방법은 **없다**.

첫 번째 조건을 어기면 세어야 할 답이 누락된다. "모든 한국인의 수를 세려는데 모든 한국인은 부산 사람이거나 대전 사람이라고 생각하는 것"과 같다. 두 번째 조건을 어기면 같은 답이 여러 번 세어진다. "모든 한국인은 열 살 이상이거나 미성년자라고 생각하는 것"과 같아서, 열 살이 넘는 미성년자는 두 번 세어진다.

맨 왼쪽 세로줄을 덮는 방법은 반드시 (1)이거나 (2)이며 동시에 둘일 수는 없으므로, 두 조건이 모두 성립한다.

### 점화식

각 분류에서 남은 부분을 채우는 방법의 수는 각각 `tiling(n - 1)`, `tiling(n - 2)`이므로 다음이 성립한다.

```text
tiling(n) = tiling(n - 1) + tiling(n - 2)
```

기저 사례는 `n ≤ 1`일 때다.

- `n = 0`: 이미 다 채워진 상태이므로 아무것도 놓지 않는 한 가지 방법이 있다.
- `n = 1`: 세로 타일 한 개를 놓는 한 가지 방법뿐이다.

둘 다 `1`이므로 `if (width <= 1) return 1;` 한 줄로 처리한다.

값을 나열해 보면 피보나치 수열과 같다. `tiling(n) = F(n + 1)`이며, 그래서 `tiling(5) = F(6) = 8`이 된다.

```text
n        1  2  3  4  5   6   7 ...
tiling   1  2  3  5  8  13  21 ...
```

### 오버플로에 유의하기

경우의 수를 세는 문제는 답 자체가 지수적으로 커지는 경우가 흔하다. `n = 100`이면 방법의 수는 64비트 정수형의 표현 범위도 훌쩍 넘어간다. 그래서 이런 문제들은 대개 답을 어떤 수 `MOD`로 나눈 나머지를 출력하도록 요구한다.

중간 계산에서도 오버플로가 나지 않는지 확인해야 한다. `tiling()`이 반환하는 최댓값은 `MOD - 1 = 1,000,000,006`이고, 이 값을 두 개 더해도 약 `2 × 10⁹`로 `2³¹ - 1 = 2,147,483,647`을 넘지 않는다. 따라서 `int`로 더한 뒤 `% MOD`를 취해도 안전하다.

> `MOD`가 조금만 더 컸다면 덧셈 도중에 `int`가 넘쳤을 것이다. 곱셈이 들어가는 문제라면 `long long`으로 올리거나 매 연산마다 나머지를 취해야 한다.

### 구현

```cpp
const int MOD = 1000000007;
int cache[101];

// 2 * width 크기의 사각형을 채우는 방법의 수를 MOD로 나눈 나머지를 반환한다.
int tiling(int width) {
    // 기저 사례: width가 1 이하일 때
    if (width <= 1) return 1;

    // 메모이제이션
    int& ret = cache[width];
    if (ret != -1) return ret;

    return ret = (tiling(width - 1) + tiling(width - 2)) % MOD;
}
```

테스트 케이스마다 캐시를 초기화한다. 입력이 항상 `[0, n]` 구간의 정수 하나뿐이므로 1차원 배열로 충분하다.

```cpp
memset(cache, -1, sizeof(cache));
cout << tiling(n) << '\n';
```

### 시간 복잡도

- 부분 문제의 수: `width`가 `0`부터 `n`까지이므로 `O(n)`
- 한 부분 문제를 푸는 데 드는 시간: 두 값을 더하므로 `O(1)`

따라서 전체 시간 복잡도는 `O(n)`이고, 공간 복잡도도 `O(n)`이다.
