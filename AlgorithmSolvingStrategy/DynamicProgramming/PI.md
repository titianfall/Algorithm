# 원주율 외우기: PI

> 원주율의 숫자 조각을 3~5자리씩 끊어 외울 때, 조각들의 난이도 합을 최소로 만드는 동적 계획법 문제다.

- 문제 ID: `PI`
- 출처: [알고스팟 - 원주율 외우기](https://algospot.com/judge/problem/read/PI)

## 문제 설명

원주율을 아주 많은 자리까지 외우는 사람들은 숫자를 몇 자리씩 끊어서 외우곤 한다. 이때 `55555`나 `123`처럼 외우기 쉬운 조각이 많이 나오도록 끊는 편이 유리하다.

주어진 숫자열을 **3자리에서 5자리까지**의 조각으로 빠짐없이 끊는다고 하자. 각 조각의 난이도는 다음과 같이 정한다.

| 조각의 모양 | 예 | 난이도 |
| --- | --- | --- |
| 모든 숫자가 같다 | `333`, `5555` | 1 |
| 숫자가 1씩 단조 증가하거나 단조 감소한다 | `23456`, `3210` | 2 |
| 두 개의 숫자가 번갈아 가며 나타난다 | `323`, `54545` | 4 |
| 숫자가 등차수열을 이룬다 | `147`, `8642` | 5 |
| 그 외 모든 경우 | `1276` | 10 |

위 조건은 위에서부터 차례대로 검사해 **가장 먼저 만족하는 규칙의 난이도**를 적용한다. 예를 들어 `2345`는 등차수열이기도 하지만 공차가 1이므로 난이도는 5가 아니라 2다.

원주율의 일부인 숫자열이 주어질 때, 이 숫자열을 3~5자리 조각으로 끊어 외울 때 나올 수 있는 **난이도 합의 최솟값**을 구하라.

## 입력

입력의 첫 줄에는 테스트 케이스의 수 `C`가 주어진다.

각 테스트 케이스는 한 줄로 주어지며, 원주율의 일부를 나타내는 숫자열이 들어 있다.

## 출력

각 테스트 케이스마다 한 줄에 최소 난이도의 합을 출력한다.

## 예제

**입력**

```text
5
12341234
11111222
12122222
22222222
12673939
```

**출력**

```text
4
2
5
2
14
```

## 제한

| 항목 | 제한 |
| --- | --- |
| 테스트 케이스 수 `C` | 50 이하 |
| 숫자열의 길이 | 8 이상 10000 이하 |

숫자열의 길이는 항상 8 이상이므로 3~5자리 조각으로 끊는 방법이 반드시 하나 이상 존재한다.

## 문제를 이해할 때 주의할 점

### 조각의 길이는 3, 4, 5 중 하나뿐이다

1자리나 2자리, 6자리 이상의 조각은 만들 수 없다. 따라서 남은 숫자가 1개나 2개가 되도록 끊는 선택은 애초에 불가능한 분할이다.

### 난이도 규칙에는 우선순위가 있다

`11111`은 "모든 숫자가 같다"와 "등차수열이다"를 동시에 만족하지만 난이도는 1이다. 여러 규칙에 해당하는 조각은 항상 더 쉬운(숫자가 작은) 쪽의 난이도를 갖는다.

### 눈앞에서 가장 쉬운 조각을 고르는 그리디로는 풀리지 않는다

앞에서부터 난이도가 가장 낮은 조각을 잘라내면 뒤쪽에 난이도 10짜리 조각이 남을 수 있다. 예제의 `12122222`처럼, 앞을 `121`(난이도 4)로 끊어야 뒤에 `22222`(난이도 1)가 남아 전체 합이 최소가 되는 경우가 있다.

### 예제 확인

- `12341234` → `1234` + `1234` = 2 + 2 = **4**
- `11111222` → `11111` + `222` = 1 + 1 = **2**
- `12122222` → `121` + `22222` = 4 + 1 = **5**
- `22222222` → `2222` + `2222` = 1 + 1 = **2**
- `12673939` → `1267` + `3939` = 10 + 4 = **14**

## 풀이

### 일만 자리나 외우라고?

입력의 크기를 보면, 어떤 방식이든지 완전 탐색으로 이 문제를 해결하기란 불가능하다는 것을 본능적으로 알 수 있습니다. 사실 이 문제의 모든 답의 수를 계산하는 방법은 그다지 간단하진 않습니다. 이것을 완전 탐색으로 세기가 절대로 불가능하다는 것을 보이기 위해서, 답의 하한을 간단하게 보이겠습니다.

길이가 7인 수열 `1111222`를 보도록 합시다. 문제의 규칙에 따르면 이 수열을 쪼갤 수 있는 방법은 두 가지입니다.

- `{1111, 222}`
- `{111, 1222}`

이때 두 자리 조각은 불가능함을 유의하십시오. `{11112, 22}`는 불가능합니다.

따라서 길이 7인 수열이 `n`개 있으면 이들을 이렇게 쪼갤 수 있는 방법의 수는 `2^n`개가 됩니다. 길이 10,000인 수열에는 길이 7인 수열이 1,428개나 들어갈 수 있습니다.

아래는 메모이제이션을 적용하지 않은 완전 탐색 알고리즘의 구현입니다.

```cpp
// 3~5자리로 쪼갤 수 없는 경우를 나타내는 값.
// 어떤 분할의 난이도 합보다도 크므로 min()에서 항상 밀려납니다.
constexpr int INF = 987654321;

// 현재 조각의 난이도를 반환
int classify(const string& s, int a, int b) {
    // 판단할 조각만 잘라낸다.
    string m = s.substr(a, b - a + 1);

    // 1. 모든 숫자가 같을때 1 : {333, 5555}
    bool allSame = true;
    for(int i = 1; i < m.size(); ++i) {
        if(m[i] != m[i - 1]) allSame = false;
    }

    if(allSame) return 1;

    // 2. 숫자가 1씩 단조 증가하거나 단조 감소할 때 2 : {23456, 3210}
    // 사실상 1 or -1 등차수열이냐
    bool progressive = true;
    int diff = m[1] - m[0];
    for(int i = 2; i < m.size(); ++i) {
        if(m[i] - m[i - 1] != diff) progressive = false;
    }

    if(progressive && (diff == 1 || diff == -1)) return 2;

    // 3. 두 개의 숫자가 번갈아가며 나타날때 4 : {323, 54545}
    bool alternating = true;
    for(int i = 0; i < m.size(); ++i) {
        if(m[i] != m[i%2]) alternating = false;
    }
    if(alternating) return 4;

    // 4. 숫자가 등차 수열을 이룰 때 5 : {147, 8642}
    if(progressive) return 5;

    // 5. 이 외의 모든 경우 10 : {17912, 331}
    return 10;
}

// 입력받은 원주율 문자열을 3~5개로 분할합니다.
int divide(const string& s, int begin) {
    // 기저 사례: 문자열을 다 사용한 경우
    if(s.size() == begin) return 0;

    // 지금까지 찾은 최소 난이도. 끝까지 INF면 쪼갤 방법이 없다는 뜻입니다.
    int ret = INF;
    for(int piece = 3; piece <= 5; ++piece) {
        // 남은 문자열이 모자랄 경우
        if(s.size() < begin + piece) break;
        
        // 뒷부분의 최소 난이도. 쪼갤 수 없으면 INF가 옵니다.
        int sub = divide(s, begin + piece);
        if(sub == INF) continue; // 뒤쪽이 쪼개지지 않는 분할
         
        // 이번 조각의 난이도 + 뒷부분의 최소 난이도
        ret = min(ret, classify(s, begin, begin + piece - 1) + sub);
    }
    return ret;
}
```

### 메모이제이션의 적용

하지만 적절한 완전 탐색 알고리즘을 만들면 메모이제이션으로 이 문제를 해결할 수 있습니다. 이 문제를 푸는 완전 탐색 알고리즘은 주어진 수열을 쪼개는 모든 방법을 하나씩 만들어 보며 그중 난이도의 합이 가장 적은 조합을 찾아냅니다. 각 재귀 함수는 한 번 불릴 때마다 첫 조각의 길이를 하나하나 시도해보며 남은 수열을 재귀적으로 쪼갭니다.

첫 조각의 길이는 3, 4, 5 중 하나입니다. 각 경우마다 하나씩의 부분 문제를 풀어야 합니다. 이때 세 개의 부분 문제에 대한 최적해를 구했다 하면, 전체 문제의 최적해는 다음 세 경우 중 가장 작은 값이 됩니다.

- 길이 3인 조각의 난이도 + 3글자 빼고 나머지 수열에 대한 최적해
- 길이 4인 조각의 난이도 + 4글자 빼고 나머지 수열에 대한 최적해
- 길이 5인 조각의 난이도 + 5글자 빼고 나머지 수열에 대한 최적해

나머지 수열의 최적해를 구할 때 앞의 부분을 어떤 식으로 쪼갰는지는 중요하지 않습니다. (최적 부분 구조가 성립한다는 말이죠.) 따라서 부분 수열의 시작 위치 `begin`이 주어졌을 때 최소 난이도를 반환하는 함수 `memorize()`를 다음과 같이 정의할 수 있습니다.

```text
memorize(begin) = min(memorize(begin + L) + classify(N(begin, L)))   (L = 3, 4, 5)
```

여기서 `N(begin, L)`은 `N[begin]`에서 시작하는 길이 `L`인 부분 문자열이고, `classify()`는 해당 조각의 난이도를 반환하는 함수라고 합시다. 이 함수는 `begin`이 같을 때 항상 같은 값을 반환하므로, 메모이제이션으로 쉽게 최적화할 수 있습니다.

## 구현

이 코드는 크게 두 부분으로 나뉩니다.

- `classify()` — 숫자의 한 조각이 주어졌을 때 난이도를 판정한다.
- `memorize()` — 실제 메모이제이션을 구현한다.

조각의 난이도를 판정하는 것은 번거롭지만 어렵거나 시간이 오래 걸리는 작업은 아닙니다. 따라서 효율성보다는 구현의 용이성과 간결함에 초점을 맞춰 구현하는 것이 좋습니다.

실제 최소의 난이도 조합을 구하는 함수 `memorize()`의 구현은 점화식으로부터 간단하게 얻을 수 있습니다. 이 알고리즘에는 최대 `n`개의 부분 문제가 있고, 각 부분 문제를 해결하는 데 최대 세 개의 부분 문제를 봅니다.

**따라서 시간 복잡도는 `O(n)`이 됩니다.**

```cpp
constexpr int INF = 987654321;
string N;

// N[a, b]난이도를 반환한다.
int classify(int a, int b) {
    // 숫자 조각을 가져온다.
    string M = N.substr(a, (b - a) + 1);

    // 첫 글자만으로 이루어진 문자열과 같으면 난이도는 1
    if(M == string(M.size(), M[0])) 
        return 1;

    // 등차 수열인지 검사한다.
    bool progressive = true;
    for(int i = 0; i < M.size() - 1; ++i) {
        if(M[i + 1] - M[i] != M[1] - M[0]) {
            progressive = false;
        }
    }

    // 등차 수열이면서 공차가 1 혹은 -1이면 난이도는 2
    if(progressive && abs(M[1] - M[0]) == 1) 
        return 2;

    // 두 수가 번갈아 등장하는지 확인한다.
    bool alternating = true;
    for(int i = 0; i < M.size(); ++i) {
        if(M[i] != M[i % 2])
            alternating = false;
    }
    // 두 수가 번갈아 등장하면 난이도 4
    if(alternating) return 4;

    // 공차가 1이 아닌 등차수열의 난이도는 5
    if(progressive) return 5;

    // 이 외는 난이도 모두 10
    return 10;
}

int cache[10002];
// 수열 N[begin..]을 외우는 방법 중 난이도의 최소 합을 출력한다.
int memorize(int begin) {
    // 기저 사례: 수열의 끝에 도달했을 경우
    if(N.size() == begin) return 0;

    // 메모이제이션
    int& ret = cache[begin];
    if(ret != -1) return ret;

    ret = INF;
    for(int L = 3; L <= 5; ++L) {
        if(begin + L <= N.size()) {
            ret = min(ret, memorize(begin + L) + classify(begin, begin + L - 1));
        }
    }
    return ret;
}
```

## 메모이제이션의 유무에 따른 시간 복잡도

### 메모이제이션이 없을 때

완전 탐색은 가능한 분할을 하나도 빠짐없이 만들어 봅니다. 따라서 걸리는 시간은 **분할의 개수**에 비례합니다.

길이 `n`인 수열을 쪼개는 방법의 수를 `f(n)`이라고 하면, 첫 조각의 길이가 3, 4, 5인 경우로 나뉘므로 다음 점화식이 성립합니다.

```text
f(n) = f(n-3) + f(n-4) + f(n-5)
```

이런 형태의 점화식은 지수적으로 증가하며, 증가율은 특성 방정식 `x^5 = x^2 + x + 1`의 실근인 약 `1.3247`입니다.

```text
f(7) = 2
f(14) = 13
f(30) = 1,208
f(100) = 427,417,260,768
```

즉 완전 탐색의 시간 복잡도는 `O(1.3247^n)`입니다. `n = 10,000`이면 대략 `10^1222`가지의 분할을 만들어 봐야 합니다. 우주의 원자 수가 약 `10^80`개이므로, 이 계산은 어떤 컴퓨터로도 끝낼 수 없습니다.

> 앞에서 하한으로 보인 `2^n`(약 `10^430`)은 "길이 7인 블록 안에서만 쪼개는" 분할만 센 값입니다. 블록 경계를 넘나드는 분할까지 세면 실제 개수는 이렇게 더 커집니다.

### 메모이제이션을 적용했을 때

`memorize(begin)`의 반환값은 오직 `begin`에만 의존합니다. 앞부분을 어떻게 쪼개고 여기까지 왔든, `begin`이 같으면 답도 같습니다. 그러므로 서로 다른 부분 문제는 `begin`이 가질 수 있는 값의 수, 즉 **`n`개뿐**입니다.

- 부분 문제의 수: `n`개
- 각 부분 문제를 푸는 비용: 조각 길이 3, 4, 5를 시도하므로 3번의 반복
- `classify()` 한 번의 비용: 조각의 길이가 최대 5로 고정이므로 `O(1)`

따라서 전체 시간 복잡도는 **`O(n)`**입니다.

### 차이

| 항목 | 완전 탐색 | 메모이제이션 |
| --- | --- | --- |
| 시간 복잡도 | `O(1.3247^n)` | `O(n)` |
| `n = 10,000`일 때 연산 횟수 | 약 `10^1222` | 약 `30,000` |
| 추가로 쓰는 메모리 | 없음 | `int` 배열 `n`칸 (약 40KB) |

두 코드의 차이는 `cache` 배열과 아래 두 줄이 전부입니다.

```cpp
int& ret = cache[begin];
if(ret != -1) return ret;
```

완전 탐색이 느린 이유는 **같은 부분 문제를 지수적으로 여러 번 다시 푸는 것**이지, 부분 문제 자체가 많아서가 아닙니다. 실제로 풀어야 할 서로 다른 문제는 처음부터 `n`개뿐이었습니다. 이 두 줄은 "이미 답을 아는 문제라면 즉시 돌려준다"고 말할 뿐인데, 그것만으로 `10^1222`가 `30,000`이 됩니다.

이것이 동적 계획법의 전부입니다. **부분 문제가 겹쳐서 나타나고(중복 부분 문제), 부분 문제의 최적해가 전체 최적해를 이루면(최적 부분 구조), 캐시 한 줄로 지수 시간을 다항 시간으로 끌어내릴 수 있습니다.**
