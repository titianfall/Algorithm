<summary><b>1. 중복되는 부분 문제</b></summary>

큰 의미에서는 분할 정복과 같은 접근 방식이다. 처음 주어진 문제를 더 작은 문제들로 나눈 뒤, 각 조각의 답을 계산하고, 그 답들로부터 원래 문제에 대한 답을 계산해 내기 때문이다.

단, 문제를 분할하는 과정에서 차이가 발생한다. 동적 계획법에서는 **어떤 부분 문제가 두 개 이상의 문제를 푸는 데 사용될 수 있다.** 따라서 같은 답을 여러 번 계산하는 대신 한 번만 계산하고, 그 결과를 재활용하여 속도 향상을 꾀할 수 있다.

- **캐시 cache**: 계산 결과를 저장해 두는 메모리 공간
- **중복되는 부분 문제 overlapping subproblem**: 두 번 이상 계산되는 부분 문제

`abcdefg`를 나누는 두 가지 방식을 비교해 보자.

![abcdefg를 abcd/efg로 나누는 방식과 abcde/cdefg로 나누는 방식의 분할 트리](<assets/abcdefg.png>)

`(a)`는 `abcd`와 `efg`로 나누어 겹치는 부분이 없다. 반면 `(b)`는 `abcde`와 `cdefg`로 나누어 `cde`가 양쪽에 모두 들어가고, 그 아래의 `c`, `de`까지 중복해서 계산하게 된다.

계산의 중복 횟수는 분할의 깊이가 깊어질수록 지수적으로 증가한다. 이를 해결하기 위해 고안된 것이 동적 계획법이다.

## 1.1 이항 계수 계산

**이항 계수 binomial coefficient**는 서로 다른 `n`개의 원소 중에서 `r`개를 순서 없이 골라내는 방법의 수다. 다음 점화식이 성립한다.

```text
nCr = (n-1)C(r-1) + (n-1)Cr
```

이 점화식을 그대로 코드로 옮길 수 있다.

```cpp
int bino(int n, int r) {
    // 기저 사례: n = r(모든 원소를 다 고르는 경우) 혹은 r = 0(고를 원소가 없는 경우)
    if(r == 0 || n == r) return 1;
    return bino(n-1, r-1) + bino(n-1, r);
}
```

`bino(4, 2)`와 `bino(8, 4)`의 함수 호출 과정을 보면 다음과 같다.

![bino(4, 2)의 호출 트리와 중복 제거 후의 트리, 그리고 bino(8, 4)의 호출 트리](<assets/bino().png>)

`(a)`에서 `bino(2, 1)`이 `bino(3, 1)`과 `bino(3, 2)` 양쪽에서 필요하다는 점이 핵심이다. 이 부분 문제를 두 번 계산하면서 그 아래의 `bino(1, 0)`, `bino(1, 1)`까지 통째로 다시 계산한다.

`(b)`처럼 한 번 계산한 결과를 캐시에 저장해 두면 같은 부분 문제는 노드 하나로 합쳐진다. 같은 노드로 화살표가 여러 개 들어오는 것이 곧 여러 곳에서 재활용된다는 뜻이다.

`(c)`의 `bino(8, 4)`를 보면 왜 이 차이가 중요한지가 드러난다. 아래로 내려갈수록 같은 부분 문제를 향한 화살표가 폭발적으로 늘어나, `bino(1, 0)`과 `bino(1, 1)`은 수십 번씩 다시 계산된다. `n`이 조금만 커져도 중복 계산량이 지수적으로 증가한다.

더 큰 `n`에 대해 `bino(n, ⌊n/2⌋)`를 호출했을 때의 함수 호출 횟수는 다음과 같다.

| `n` | 2 | 3 | 4 | 5 | 6 | ... | 18 | 19 | ... | 24 | 25 |
| --- | ---: | ---: | ---: | ---: | ---: | :---: | ---: | ---: | :---: | ---: | ---: |
| `bino()` 호출 횟수 | 3 | 5 | 11 | 19 | 39 | ... | 97,239 | 184,755 | ... | 5,408,311 | 10,400,599 |
| `bino2()` 호출 횟수 | 3 | 5 | 8 | 11 | 15 | ... | 99 | 109 | ... | 168 | 181 |

`n`이 1 커질 때마다 `bino()`의 호출 횟수는 대략 두 배가 된다. `n = 25`에서 이미 천만 번을 넘고, `n = 50`이면 현실적인 시간 안에 끝나지 않는다. 반면 캐시를 사용하는 `bino2()`는 같은 구간에서 181번에 그친다.

## 1.2 메모이제이션

한 번 계산한 값을 캐시에 저장해 두고, 같은 부분 문제를 다시 만나면 계산 없이 저장된 값을 반환하는 기법을 **메모이제이션 memoization**이라고 한다.

```cpp
// -1로 초기화해 둔다.
int cache[30][30];

int bino2(int n, int r) {
    // 기저 사례: n = r(모든 원소를 다 고르는 경우) 혹은 r = 0(고를 원소가 없는 경우)
    if(r == 0 || n == r) return 1;
    // -1이 아니라면 한 번 계산한 값을 곧장 반환한다.
    if(cache[n][r] != -1) return cache[n][r];
    // 직접 계산한 뒤 배열에 저장
    return cache[n][r] = bino2(n-1, r-1) + bino2(n-1, r);
}
```

```cpp
memset(cache, -1, sizeof(cache)); // 전역변수로 초기화하는 방법
```

### 메모이제이션을 적용할 수 있는 경우

```cpp
int counter = 0;
int count() {
    return counter++;
}
```

해당 함수는 입력을 전혀 받지 않으면서도 매번 다른 결과를 반환한다. 반면 `bino()`처럼 입력이 같으면 출력도 항상 동일한 함수도 작성할 수 있다.

함수의 반환 값이 그 입력 값만으로 결정되는지 여부를 **참조적 투명성 referential transparency**이라고 한다. 입력이 고정되어 있을 때 그 결과가 항상 같은 함수들을 **참조적 투명 함수 referentially transparent function**라고 한다.

메모이제이션은 이처럼 참조적 투명 함수에만 적용이 가능하다. 입력이 같은데도 외부 요소에 따라 다른 값이 반환된다면 캐싱을 할 수 없기 때문이다.

### 메모이제이션 구현 패턴

동적 계획법은 가장 흔한 문제 유형 중 하나이기 때문에 메모이제이션은 굉장히 자주 구현하게 된다. 때문에 한 가지 패턴을 정해 두고 항상 같은 형태로 구현하기로 하면 작성하기도, 버그를 찾기도 쉬워진다.

```cpp
// a와 b는 각각 [0, 2500) 구간 안의 정수
// 반환 값은 항상 int형 안에 들어가는 음이 아닌 정수이다.
int someObscureFunction(int a, int b);
```

해당 함수를 한 번 계산하는 데 오랜 시간이 걸리는 참조적 투명 함수라고 가정할 때, 이 코드를 메모이제이션으로 구현하는 방법은 다음과 같다.

```cpp
// 전부 -1로 초기화해준다.
int cache[2500][2500];

// a와 b는 각각 [0, 2500) 구간 안의 정수
// 반환 값은 항상 int형 안에 들어가는 음이 아닌 정수이다.
int someObscureFunction(int a, int b) {
    // 기저 사례를 처음에 처리한다.
    if(...) return ...;

    // (a, b)에 대한 답을 구한 적이 있으면 곧장 반환
    int& ret = cache[a][b];
    if(ret != -1) return ret;

    // 여기에서 답을 계산한다.
    ...
    return ret;
}

int main() {
    // memset()을 이용해 cache 배열을 초기화한다.
    // #include <cstring>
    memset(cache, -1, sizeof(cache));
}
```

1. **항상 기저 사례를 먼저 처리한다.**  
   입력이 범위를 벗어난 경우 등을 기저 사례로 처리한다. 기저 사례를 확인하지 않고 `cache[]`에 접근하면 범위를 벗어나는 등의 오류가 있을 수 있다.

2. **함수의 반환 값이 항상 0 이상이라는 점을 이용해 `cache[]`를 모두 `-1`로 초기화한다.**  
   해당 위치에 적혀 있는 값이 `-1`이라면 이 값은 계산된 반환 값일 리 없음을 알 수 있다. 단, 반환 값이 음수일 수 있다면 쓸 수 없는 방법이다.

3. **`ret`가 `cache[a][b]`에 대한 참조형 reference이라는 데 유의한다.**  
   참조형 `ret`의 값을 바꾸면 `cache[a][b]`의 값도 변한다. 때문에 답을 저장할 때도 매번 귀찮게 `cache[a][b]`라고 쓸 필요가 없어진다. 이 트릭은 특히 `cache`가 다차원 배열일 때 유용하다. 귀찮기는 둘째치고, 인덱스 순서를 바꿔 쓴다거나 하는 실수를 할 가능성을 없애 준다.

4. **`memset()`을 이용해 `cache[]`를 초기화한다.**  
   메모이제이션용 배열을 초기화하는 것은 매우 자주 하는 일이다. 다중 `for`문보다 쉽게 초기화하는 방법을 알면 간편하다. 단, `memset()`으로 배열을 초기화하는 방식은 굉장히 제한적인 상황에만 쓸 수 있으므로 유의한다.

### 메모이제이션의 시간 복잡도 분석

메모이제이션의 시간 복잡도를 분석하는 과정은 처음에는 약간 헷갈릴 수 있다. 각 입력에 대해 함수를 처음으로 호출할 때와 다음으로 호출할 때 걸리는 시간이 다르기 때문이다.

그러나 메모이제이션을 사용하는 알고리즘의 시간 복잡도를 굉장히 간단하게 계산할 수 있는 방법이 있다. 바로 다음 식을 이용하는 것이다.

```text
(존재하는 부분 문제의 수) × (한 부분 문제를 풀 때 필요한 반복문의 수행 횟수)
```

위 식을 이항 계수 `bino2()`에 적용해 보자.

- `r`의 최대치는 `n`이니 `bino2(n, r)`을 계산할 때 만날 수 있는 부분 문제의 수는 최대 `O(n²)`이다.
- 각 부분 문제를 계산할 때 걸리는 시간은 반복문이 없으니 `O(1)`이다.

그러면 위 식에 따라 `bino2(n, r)`을 계산하는 데 걸리는 시간 복잡도는 다음과 같다.

```text
O(n²) × O(1) = O(n²)
```

# 2. 최적 부분 구조

**최적 부분 구조 optimal substructure**란, 전체 문제의 최적해가 더 작은 부분 문제들의 최적해로 구성되는 성질이다. 동적 계획법은 이 성질이 있을 때 부분 문제의 답을 저장하고 조합해 전체 문제를 해결할 수 있다.

TRIANGLEPATH에서는 어느 쪽으로 내려갈지의 선택에 따라 문제를 두 개의 부분 문제로 분할할 수 있었다. 이때 지금까지의 선택과 상관없이 각 부분 문제를 최적으로 풀기만 하면 전체 문제의 최적해도 알 수 있다. 따라서 최적 부분 구조가 성립한다.

다른 예로 서울에서 부산까지 가는 최단 경로를 들 수 있다.

> 이 최단 경로가 대전을 지난다고 가정하자. 이 경로를 (서울, 대전), (대전, 부산)으로 나누고 두 구간의 최단 경로를 찾아서 둘을 이으면 항상 서울에서 부산으로 가는 최단 경로를 얻을 수 있다.

반면 더 작은 문제의 최적해만으로는 전체 문제의 최적해를 구할 수 없다면, 해당 문제에는 최적 부분 구조가 존재하지 않는다고 말한다.

> 예를 들어 서울에서 부산으로 향하되 고속도로 통행료의 합이 3만 원을 초과하지 않는 최단 경로를 찾고 싶다고 하자. 대전에서 부산으로 가는 경로가 두 개 있다.
>
> - 경로 A: 통행 시간 2시간, 통행료 1만 원
> - 경로 B: 통행 시간 1시간, 통행료 2만 원
>
> 이 두 경로 중 무엇을 쓸지는 서울-대전 구간의 통행료에 따라 결정된다. 서울-대전 구간의 통행료가 1.5만 원이라면, 남은 통행료 예산이 부족해 경로 B 대신 경로 A를 쓰게 된다.

따라서 이 문제에서는 부분 문제의 최적해가 전체 문제의 최적해로 연결되지 않을 수도 있으며, 최적 부분 구조가 존재하지 않는다. 이런 경우에는 부분 문제 정의에 지금까지 지출한 통행료를 포함시키는 등의 작업이 필요해진다.

최적 부분 구조는 대개 직관적으로 이해할 수 있어 증명이 따로 필요하지 않다. 다만 직관적이지 않은 경우에는 보통 귀류법이나 대우를 이용해 증명하게 된다.

# 3. 최적화 문제 동적 계획법 레시피

최적화 문제를 동적 계획법으로 푸는 사고 과정을 다음과 같이 정리할 수 있다.

1. **완전 탐색 설계** — 모든 답을 만들어 보고 그중 최적해의 점수를 반환하는 완전 탐색 알고리즘을 설계한다.
2. **부분 문제 정의 바꾸기** — 전체 답의 점수를 반환하는 대신, 앞으로 남은 선택들에 해당하는 점수만 반환하도록 부분 문제의 정의를 바꾼다.
3. **입력 걸러내기** — 재귀 호출의 입력에 이전 선택과 관련된 정보가 있다면, 꼭 필요한 것만 남기고 줄인다. 문제에 최적 부분 구조가 성립한다면 이전 선택에 관한 정보를 아예 없앨 수도 있다.
   > 목표는 중복되는 부분 문제를 최대한 많이 만드는 것이다. 입력의 종류가 줄어들수록 더 많은 부분 문제가 겹치고, 따라서 메모이제이션을 최대한 활용할 수 있다.
4. **입력을 정수로 바꾸기** — 입력이 배열이나 문자열이라면, 가능한 경우 적절한 변환을 통해 메모이제이션할 수 있는 형태로 바꾼다.
5. **메모이제이션** — 계산 결과를 캐시에 저장해 같은 부분 문제를 다시 풀지 않도록 한다.

삼각형 위의 최대 경로(TRIANGLEPATH) 문제를 해결한 과정을 이 레시피에 맞추어 되짚어 보자.

| 단계 | TRIANGLEPATH 적용 |
| --- | --- |
| **1. 완전 탐색 설계** | 모든 경로를 만들어 보고 전체 합 중 최댓값을 반환하는 `path1()`을 만든다. |
| **2. 부분 문제 정의 바꾸기** | `path1()`이 전체 합 대신 `(y, x)` 이후에 만나는 숫자들의 최대 합만 반환하도록 바꾼다. |
| **3. 입력 걸러내기** | 정의를 바꾼 덕분에 이전 선택 정보인 `sum`을 받을 필요가 없어진다. (최적 부분 구조가 성립하기 때문) |
| **4. 입력을 정수로 바꾸기** | 이 문제에서는 필요하지 않다. |
| **5. 메모이제이션** | `cache[y][x]`에 결과를 저장한다. |

4번은 삼각형 문제에서는 쓸 일이 없었다. 4번의 예로는 최대 증가 부분 수열(LIS) 문제를 들 수 있는데, 부분 수열 `A`가 항상 `S`의 부분 수열이고 `S`의 각 위치에 1:1로 대응된다는 점을 이용해 입력을 배열에서 정수로 바꾼 것이 이에 해당한다.
