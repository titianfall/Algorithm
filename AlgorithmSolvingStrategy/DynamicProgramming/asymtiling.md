# 비대칭 타일링: ASYMTILING

> [타일링 방법의 수 세기(TILING2)](<tiling2.md>)에서 센 것은 `2 × n` 사각형을 덮는 **모든** 타일링 방법의 수였다. 이 문제는 그중 **좌우 대칭이 아닌** 타일링만 센다.
>
> 핵심은 완전 탐색에서 시작하지 않는 것이다. 이미 풀어 둔 `tiling()`을 부품으로 쓰면 훨씬 쉽게 풀린다.

## 문제 설명

그림과 같이 `2 × n` 크기의 직사각형을 `2 × 1` 크기의 타일로 채우려고 합니다. 타일들은 서로 겹쳐서는 안 되고, 90도로 회전해서 쓸 수 있습니다. **단 이 타일링 방법은 좌우 대칭이어서는 안 됩니다.**

앞의 그림은 `2 × 5` 크기의 직사각형을 채우는 비대칭 타일링 방법 여섯 가지를 보여줍니다.

```text
n = 5 → 비대칭 타일링 6가지

┌─┬─┬─┬───┐   ┌─┬─┬───┬─┐   ┌─┬───┬─┬─┐
│ │ │ ├───┤   │ │ ├───┤ │   │ ├───┤ │ │
└─┴─┴─┴───┘   └─┴─┴───┴─┘   └─┴───┴─┴─┘

┌───┬─┬─┬─┐   ┌─┬───┬───┐   ┌───┬───┬─┐
├───┤ │ │ │   │ ├───┼───┤   ├───┼───┤ │
└───┴─┴─┴─┘   └─┴───┴───┘   └───┴───┴─┘
```

다음의 두 가지는 좌우대칭이기 때문에 세지 않습니다.

```text
┌───┬─┬───┐   ┌─┬─┬─┬─┬─┐
├───┤ ├───┤   │ │ │ │ │ │
└───┴─┴───┘   └─┴─┴─┴─┴─┘
```

`n`이 주어질 때 가능한 비대칭 타일링 방법의 수를 계산하는 프로그램을 작성하세요. 방법의 수는 매우 클 수 있으므로, `1,000,000,007`로 나눈 나머지를 출력해야 합니다.

## 시간 및 메모리 제한

프로그램은 1초 안에 실행되어야 하며, 64MB 이하의 메모리를 사용해야 합니다.

## 입력

입력의 첫 줄에는 테스트 케이스의 수 `C(1 ≤ C ≤ 50)`가 주어집니다.

그 후 각 줄에 사각형의 너비 `n(1 ≤ n ≤ 100)`이 주어집니다.

## 출력

각 테스트 케이스마다 한 줄에 비대칭 타일링 방법의 수를 `1,000,000,007`로 나눈 나머지를 출력합니다.

## 제한

| 항목 | 제한 |
| --- | --- |
| 시간 제한 | 1초 (1,000ms) |
| 메모리 제한 | 64MB (65,536KB) |
| 테스트 케이스 수 `C` | 1 이상 50 이하 |
| 사각형의 너비 `n` | 1 이상 100 이하 |
| 나머지 연산의 법 `MOD` | 1,000,000,007 |

## 예제

**입력**

```text
3
2
4
92
```

**출력**

```text
0
2
913227494
```

| `n` | 전체 `tiling(n)` | 대칭 | 비대칭 |
| ---: | ---: | ---: | ---: |
| 2 | 2 | 2 | **0** |
| 4 | 5 | 3 | **2** |

`n = 2`일 때 가능한 타일링은 세로 타일 두 개와 가로 타일 두 개뿐인데 둘 다 좌우 대칭이므로 답은 `0`이다.

## 접근 1: 전체에서 대칭을 빼기

### 완전 탐색의 함정

지금까지 모든 문제를 1. '완전 탐색 알고리즘을 만들고' 2. '메모이제이션을 적용한다'는 과정으로 풀어왔기 때문에, 이 문제도 모든 비대칭 타일링을 직접 세어 보는 완전 탐색 알고리즘에서 시작하겠다는 생각을 하기 쉽습니다.

그러나 이 문제처럼 이미 풀어 본 문제의 변형된 형태를 만나면, 이 문제를 직접적으로 풀기보다는 단순화된 문제의 해법을 이용해서 더 쉽게 풀 수 있는 경우가 있습니다.

> **힌트는 모든 타일링은 대칭이거나 비대칭이라는 데서 옵니다.**
>
> 이때 모든 타일링 방법의 수는 `tiling()`에서 센 적이 있지요. 대칭 타일링 방법의 수를 셀 수 있다면 비대칭 타일링 방법의 수는 단순히 전체 타일링 방법의 수에서 대칭 타일링을 빼서 얻을 수 있을 겁니다.

```text
비대칭 타일링의 수 = 전체 타일링의 수 - 대칭 타일링의 수
```

그리고 다행히 대칭 타일링의 수는 비대칭 타일링의 수보다 훨씬 세기 쉽습니다. (애초에 대칭 타일링이 더 세기 어렵다면 이쪽을 계산하라는 문제를 냈겠지요.)

### 대칭 타일링의 수 세기

대칭 타일링의 수를 세는 첫 번째 단계는 `n`이 짝수인 경우와 홀수인 경우를 각각 나눠 보는 것입니다.

**(a) `n`이 홀수인 경우** — 타일링 방법이 대칭이기 위해서는 항상 정가운데 있는 세로줄은 세로 타일 하나로 덮여야만 합니다. 그리고 왼쪽 절반은 오른쪽 절반과 서로 대칭이어야겠지요.

```text
┌───────┬─┬───────┐
│░░░░░░░│ │       │      회색을 채우면 오른쪽은 자동 결정
└───────┴─┴───────┘
  width/2                → tiling(width/2)
```

**(b) `n`이 짝수, 정가운데 세로줄 둘을 가로 타일로 덮는 경우**

```text
┌─────┬───┬─────┐
│░░░░░├───┤     │
└─────┴───┴─────┘
 width/2-1               → tiling(width/2 - 1)
```

**(c) `n`이 짝수, 절반으로 나뉜 부분들이 서로 대칭인 경우**

```text
┌───────┬───────┐
│░░░░░░░│       │
└───────┴───────┘
  width/2                → tiling(width/2)
```

이제 각 경우에서, 왼쪽의 회색 부분을 채우고 나면 오른쪽 회색 부분은 대칭이기 때문에 자연스럽게 결정됩니다. 결국 이 방법들은 **회색 부분 하나를 채우는 방법과 1:1 대응**되지요. 따라서 각 경우의 수는 우리가 전에 작성했던 `tiling()`을 이용해 간단하게 구현할 수 있습니다.

| `n` | 대칭 타일링의 수 |
| --- | --- |
| 홀수 | `tiling(n/2)` |
| 짝수 | `tiling(n/2) + tiling(n/2 - 1)` |

### 구현 (코드 8.19)

```cpp
const int MOD = 1000000007;

// 2*width 크기의 사각형을 채우는 비대칭 방법의 수를 반환한다.
// 전체 타일링의 수에서 대칭 타일링의 수를 빼는 방식이다.
int asymmetric(int width) {
    // [width가 홀수] 대칭 타일링은 (a) 한 종류뿐이다.
    //   정가운데 세로줄은 반드시 세로 타일 하나로 덮이고,
    //   왼쪽 절반(width/2)을 채우면 오른쪽 절반은 대칭으로 자동 결정된다.
    //   → 대칭 타일링의 수 = tiling(width/2)
    // 뺄셈 결과가 음수가 되지 않도록 MOD를 미리 더한 뒤 나머지를 취한다.
    if(width % 2 == 1)
        return (tiling(width) - tiling(width/2) + MOD) % MOD;

    // [width가 짝수] 대칭 타일링에 두 종류가 있으므로 둘 다 빼 준다.
    int ret = tiling(width);

    // (c) 정가운데에서 절반으로 나뉘고 양쪽이 서로 대칭인 경우
    //     → 왼쪽 절반을 채우는 방법의 수 = tiling(width/2)
    ret = (ret - tiling(width/2) + MOD) % MOD;

    // (b) 정가운데 세로줄 둘을 가로 타일로 덮고 나머지가 서로 대칭인 경우
    //     → 가로 타일이 차지한 한 칸을 뺀 나머지 = tiling(width/2 - 1)
    ret = (ret - tiling(width/2-1) + MOD) % MOD;

    return ret;
}
```

> `tiling()`은 `MOD`로 나눈 나머지를 반환하므로, 빼기 전에 항상 `+ MOD`를 해 주어야 한다. 자세한 이유는 [바로 아래](#왜--mod를-하는가)에서 다룬다.

### 왜 `+ MOD`를 하는가

코드 8.19는 `tiling()`을 직접 호출해 이 문제를 해결합니다. 짝수와 홀수 `n`을 따로 처리한 부분과, 두 값을 뺀 후 `MOD`로 나누기 전에 `MOD`를 미리 더해 주는 부분을 눈여겨보세요.

> **주의**: `tiling()`의 반환 값은 경우의 수이기 때문에 결코 음수일 수 없습니다. 그러나 `tiling()`은 `MOD`로 나눈 나머지를 반환하기 때문에, **실제 경우의 수가 양수라도 두 수를 뺀 값은 음수일 수 있지요.**
>
> 예를 들어 `2 × width`를 채우는 방법의 수가 `MOD + 1`가지이고 `2 × (width/2)`를 채우는 방법의 수가 `100`가지라면,
>
> ```text
> tiling(width)   = (MOD + 1) % MOD = 1
> tiling(width/2) = 100
> 1 - 100 = -99      ← 음수!
> ```
>
> `MOD`를 더하는 이유는 이런 문제를 방지하기 위함입니다.

`asymmetric()`의 실행 자체는 상수 시간에 이루어지므로 이 문제의 시간 복잡도는 `tiling()`과 똑같이 `O(n)`이 됩니다.

## 접근 2: 직접 비대칭 타일링의 수 세기

물론 이렇게 돌아가지 않고 직접 비대칭 타일링의 수를 셀 수도 있습니다. 이쪽은 조금 더 까다롭지만, 그렇다고 못 할 일은 아닙니다.

### 왜 앞에서부터 만들면 안 되는가

비대칭 타일링의 수를 세는 간단한 방법은 모든 타일링 방법을 만들어 보고 이 중 좌우 대칭이 아닌 것만을 걸러내는 것입니다.

그러나 이런 방법으로는 **메모이제이션을 적용할 수가 없죠.** 타일링 방법이 대칭인지 판단하기 위해서는 과거에 선택한 조각들에 대한 정보를 전부 재귀 호출에 전달해야 하기 때문입니다.

### 양쪽 끝에서 동시에 만들어 나가기

메모이제이션에 과거 조각의 정보를 전부 전달하지 않고서도 문제를 해결할 수 있는 방법은 맨 앞에서부터 타일링 방법을 만들어 가는 것이 아니라 **양쪽 끝에서부터 동시에 만들어 나가는 것**입니다.

다음은 타일링 방법을 양쪽 끝을 덮은 타일들로 분류하는 방법입니다.

```text
(a) 양쪽 끝이 세로 타일          (b) 양쪽 끝이 가로 타일

┌─┬─────────┬─┐              ┌───┬─────────┬───┐
│ │░░░░░░░░░│ │              ├───┤░░░░░░░░░├───┤
└─┴─────────┴─┘              └───┴─────────┴───┘
    width-2                          width-4

(c) 왼쪽 세로 / 오른쪽 가로      (d) 왼쪽 가로 / 오른쪽 세로

┌─┬─────────┬───┐            ┌───┬─────────┬─┐
│ │░░░░░░░░░├───┤            ├───┤░░░░░░░░░│ │
└─┴─────────┴───┘            └───┴─────────┴─┘
    width-3                          width-3
```

이때 (a)와 (b)에서는 양쪽 끝을 덮은 타일들이 서로 **대칭**이고, (c)와 (d)에서는 양쪽 끝을 덮은 타일들이 서로 **대칭이 아닙니다**. `2 × n` 사각형을 비대칭 형식으로 덮는 타일링 방법은 모두 이 네 가지 패턴 중 정확히 하나에 속하지요.

이제 각 패턴별로 몇 개의 타일링 방법이 있는지는 쉽게 계산할 수 있습니다.

- **(a), (b)**: 가운데 남은 회색 부분을 덮는 방법을 재귀 호출로 찾습니다. 물론 이 방법은 **대칭이 아니어야** 합니다. 이 부분까지 좌우 대칭이라면 전체 타일링 방법이 대칭이 되어버리니까요.
- **(c), (d)**: 가운데 남은 회색 부분을 덮는 방법을 찾습니다. 이 방법은 **대칭이라도 상관없습니다.** 회색 부분이 내부적으로 대칭이더라도, 양쪽 끝이 서로 대칭이 아니므로 전체 타일링 방법은 비대칭이 되기 때문이죠.

| 패턴 | 왼쪽 끝 | 오른쪽 끝 | 남는 너비 | 가운데를 세는 방법 |
| :---: | --- | --- | :---: | --- |
| (a) | 세로 | 세로 | `width-2` | `asymmetric2(width-2)` |
| (b) | 가로 | 가로 | `width-4` | `asymmetric2(width-4)` |
| (c) | 세로 | 가로 | `width-3` | `tiling(width-3)` |
| (d) | 가로 | 세로 | `width-3` | `tiling(width-3)` |

(a)와 (b)는 재귀 호출로 해결하고, (c)와 (d)는 `tiling()`을 이용해 해결하면 코드 8.20을 얻을 수 있습니다. `asymmetric2()`는 `O(n)`개의 입력에 대해 각각 상수 시간으로 답을 계산하므로, 전체 시간 복잡도는 `O(n)`입니다.

### 구현 (코드 8.20)

```cpp
int cache2[101];
// 2*width 크기의 사각형을 채우는 비대칭 방법의 수를 반환한다.
int asymmetric2(int width) {
    // 기저 사례: 너비가 2 이하인 경우
    if(width <= 2) return 0;
    // 메모이제이션
    int& ret = cache2[width];
    if(ret != -1) return ret;
    ret = asymmetric2(width-2) % MOD;            // (a)
    ret = (ret + asymmetric2(width-4)) % MOD;    // (b)
    ret = (ret + tiling(width-3)) % MOD;         // (c)
    ret = (ret + tiling(width-3)) % MOD;         // (d)
    return ret;
}
```

기저 사례가 `0`인 이유는 너비가 2 이하인 사각형의 타일링은 모두 좌우 대칭이기 때문이다.

```text
비대칭 타일링 전체
 = (a) 양끝 세로   : 가운데(width-2)가 비대칭   → asymmetric2(width-2)
 + (b) 양끝 가로   : 가운데(width-4)가 비대칭   → asymmetric2(width-4)
 + (c) 세로 | 가로 : 가운데(width-3)는 아무거나 → tiling(width-3)
 + (d) 가로 | 세로 : 가운데(width-3)는 아무거나 → tiling(width-3)
```

(c)와 (d)에 같은 `tiling(width-3)`이 두 번 나오는 것은 실수가 아니라, **서로 다른 두 패턴이 우연히 같은 개수를 갖기 때문**이다.

#### `n = 5`로 확인하기

세로 타일을 `1`, 가로 타일 두 개를 `2`로 적으면 다음과 같다.

| 패턴 | 형태 | 가운데 | 개수 | 해당 타일링 |
| :---: | --- | --- | ---: | --- |
| (a) | `1 … 1` | 너비 3, 비대칭만 | `asymmetric2(3)` = 2 | `1121`, `1211` |
| (b) | `2 … 2` | 너비 1, 비대칭만 | `asymmetric2(1)` = 0 | — (`212`는 대칭) |
| (c) | `1 … 2` | 너비 2, 전부 | `tiling(2)` = 2 | `1112`, `122` |
| (d) | `2 … 1` | 너비 2, 전부 | `tiling(2)` = 2 | `2111`, `221` |
| | | | **합 6** | 문제의 여섯 가지와 일치 |

(b)가 `0`인 것이 배타성이 잘 작동한다는 증거다. `2|1|2` = `212`는 양끝이 대칭이라 (b)에 속하는데, 가운데 `1`도 대칭이라 전체가 대칭이 되어 세면 안 된다. 실제로 `asymmetric2(1) = 0`이 이를 걸러낸다.

### 캐시가 실제로 어떻게 쓰이는가

`asymmetric2(7)`을 실행하면서 호출을 전부 찍어 본 것이다. `★HIT`이 캐시를 재사용한 지점이다.

```text
asymmetric2(7)
│
├─ asymmetric2(5)                       (a) 양끝 세로
│  ├─ asymmetric2(3)                    (a)
│  │  ├─ asymmetric2(1)  = 0   기저
│  │  ├─ asymmetric2(-1) = 0   기저     ← 음수도 기저가 받아낸다
│  │  ├─ tiling(0)       = 1   기저
│  │  └─ tiling(0)       = 1   기저
│  │     ⇒ 0+0+1+1 = 2         cache2[3] ← 2
│  ├─ asymmetric2(1)     = 0   기저
│  ├─ tiling(2)
│  │  ├─ tiling(1) = 1   기저
│  │  └─ tiling(0) = 1   기저
│  │     ⇒ 2                   cache[2] ← 2
│  └─ tiling(2)          = 2   ★HIT
│     ⇒ 2+0+2+2 = 6            cache2[5] ← 6
│
├─ asymmetric2(3)        = 2   ★HIT     ← (b), 이미 계산해 둔 값
│
├─ tiling(4)
│  ├─ tiling(3)
│  │  ├─ tiling(2) = 2   ★HIT
│  │  └─ tiling(1) = 1   기저
│  │     ⇒ 3                   cache[3] ← 3
│  └─ tiling(2)    = 2   ★HIT
│     ⇒ 5                      cache[4] ← 5
│
└─ tiling(4)             = 5   ★HIT     ← (d), (c)에서 방금 계산한 값

   ⇒ 6 + 2 + 5 + 5 = 18        cache2[7] ← 18
```

#### 단계별 캐시 상태

| 단계 | 무슨 일이 일어나는가 | `cache[]` (tiling) | `cache2[]` (asymmetric2) |
| ---: | --- | --- | --- |
| 1 | `asymmetric2(7)` 진입 — 캐시가 비어 있어 계산 시작 | — | — |
| 2 | ↳ `asymmetric2(5)` 진입 | — | — |
| 3 | ↳↳ `asymmetric2(3)` 완성 — 기저만 써서 `0+0+1+1` | — | `[3]=2` |
| 4 | ↳ `tiling(2)` 계산 `1+1` | `[2]=2` | `[3]=2` |
| 5 | ↳ `tiling(2)` 재호출 → **HIT** | `[2]=2` | `[3]=2` |
| 6 | ↳ `asymmetric2(5)` 완성 `2+0+2+2` | `[2]=2` | `[3]=2` `[5]=6` |
| 7 | `asymmetric2(3)` 재호출 → **HIT** | `[2]=2` | `[3]=2` `[5]=6` |
| 8 | `tiling(4)` 계산 (내부에서 `tiling(2)` **HIT**) | `[2]=2` `[3]=3` `[4]=5` | `[3]=2` `[5]=6` |
| 9 | `tiling(4)` 재호출 → **HIT** | 그대로 | 그대로 |
| 10 | `asymmetric2(7)` 완성 `6+2+5+5` | 그대로 | `[3]=2` `[5]=6` `[7]=18` |

```text
최종 캐시 (-1 = 계산한 적 없음)

  w        :    0    1    2    3    4    5    6    7
  cache [] :   -1   -1    2    3    5   -1   -1   -1
  cache2[] :   -1   -1   -1    2   -1    6   -1   18
```

여기서 두 가지가 보인다.

- `cache2[]`는 **홀수 자리만** 채워졌다. `width`가 `2`씩 줄어드는 재귀라 짝수 쪽으로는 갈 일이 없다.
- `cache[]`는 `[4]`까지만 채워졌다. `asymmetric2(7)`이 필요로 하는 가장 큰 `tiling`이 `tiling(7-3)`이기 때문이다. **필요한 부분 문제만 계산하는 것**이 메모이제이션(하향식)의 성질이다.

#### 캐시가 없다면

| | `asymmetric2` 호출 | `tiling` 호출 | 합계 |
| ---: | ---: | ---: | ---: |
| `n = 7` | 9 | 28 | **37** |
| `n = 20` | 177 | 21,428 | **21,605** |
| `n = 30` | 1,973 | 2,687,372 | **2,689,345** |
| `n = 40` | 21,891 | 331,102,970 | **331,124,861** |

`n`이 10 커질 때마다 약 100배씩 늘어난다. `tiling()`이 자기 자신을 두 번 부르는 구조라 호출 수가 피보나치 수만큼, 즉 지수적으로 폭발하기 때문이다.

캐시를 붙이면 `asymmetric2`와 `tiling` 각각 `width`당 **한 번씩만** 계산하므로 전체가 `O(n)`이 된다. 위 `n = 7` 추적에서도 `tiling()`이 12번 호출됐지만 실제 계산은 3번뿐이었다.

```text
n = 7 실측
  tiling()      : 호출 12회 = 계산  3회 + 캐시 HIT 4회 + 기저 5회
  asymmetric2() : 호출  7회 = 계산  3회 + 캐시 HIT 1회 + 기저 3회
```

## 스캐폴딩으로 테스트하기

이 문제는 스캐폴딩을 통해 테스트하기 아주 적절한 문제입니다. 두 가지 조건을 모두 갖췄기 때문이죠.

1. **입력을 생성하기 쉽다** — 1부터 100까지의 정수입니다.
2. **느리지만 정답임을 확실히 알 수 있는 알고리즘이 존재한다** — 모든 타일링 방법을 만들어 보고 대칭인지 확인하기.

비록 느린 알고리즘이라고 해도 1부터 20 이하의 입력 정도는 쉽게 계산할 수 있기 때문에, 이들을 모두 계산해 보고 답이 일치한다면 답의 정확도에 대한 자신이 좀더 생기겠지요.

### 무엇을 만드는가

같은 문제를 푸는 **서로 독립적인 두 구현**을 만들고 답을 비교한다.

| | 역할 | 특징 |
| --- | --- | --- |
| 구현 A | 검증 대상 | `asymmetric()`, `asymmetric2()` — 빠르지만 틀렸을 수 있다 |
| 구현 B | 정답지 | 브루트포스 — 느리지만 확실히 맞다 |

### 브루트포스 설계

**1. 검증 대상과 다른 원리로 짠다.** 이게 가장 중요하다. 정답지도 점화식으로 짜면 같은 착각을 두 번 반복해 **둘 다 틀리고도 일치**할 수 있다. 그래서 `2 × n` 판에 도미노를 실제로 하나씩 올려 그림을 완성하는 방식을 쓴다.

**2. 판을 문자 배열로 표현한다.** `board[y][x]`에 그 칸을 덮은 타일의 정체를 적어 둔다.

```text
'V' : 세로 타일이 덮은 칸 (위아래 두 칸이 모두 'V')
'L' : 가로 타일의 왼쪽 칸
'R' : 가로 타일의 오른쪽 칸

예) n = 5, "세로, 가로, 가로"
     x =  0  1  2  3  4
     y=0   V  L  R  L  R
     y=1   V  L  R  L  R
```

이렇게 하면 "타일링이 같다"가 "배열이 같다"가 되어 대칭 판정이 단순해진다.

**3. 대칭 판정은 좌우로 뒤집어 비교한다.** `x`번 칸은 뒤집으면 `n-1-x` 자리로 간다. 이때 가로 타일은 왼쪽 칸과 오른쪽 칸의 역할이 바뀌므로 `L ↔ R`을 맞바꿔 줘야 한다. 세로 타일은 뒤집어도 그대로 `V`다.

```cpp
bool isSymmetric() {
    for (int y = 0; y < 2; ++y)
        for (int x = 0; x < n; ++x) {
            char mirrored = board[y][n - 1 - x];
            if (mirrored == 'L') mirrored = 'R';
            else if (mirrored == 'R') mirrored = 'L';
            if (mirrored != board[y][x]) return false;
        }
    return true;
}
```

**4. 브루트포스에도 배타성 문제가 있다.** 아무 빈칸에나 타일을 놓게 하면 순서만 다르고 결과가 같은 타일링이 여러 번 만들어진다. 그래서 규칙을 하나 강제한다.

> **항상 "가장 왼쪽, 그중 가장 위" 빈칸을 먼저 덮는다.**

이러면 매 단계에서 채울 칸이 하나로 정해지고 그 칸을 덮는 타일의 모양도 최대 두 가지뿐이라, 하나의 타일링에 도달하는 경로가 유일해져 중복이 원천적으로 사라진다. TILING2에서 "맨 왼쪽 세로줄을 기준으로 삼는다"와 같은 발상이다.

```cpp
void search() {
    // 1) 가장 왼쪽 위의 빈칸을 찾는다
    int y = -1, x = -1;
    for (int c = 0; c < n && y == -1; ++c)
        for (int r = 0; r < 2; ++r)
            if (board[r][c] == 0) { y = r; x = c; break; }

    // 2) 빈칸이 없다 == 타일링 하나가 완성됐다
    if (y == -1) {
        ++bfTotal;
        if (!isSymmetric()) ++bfAsym;
        return;
    }

    // 3) 세로 타일로 덮기 (빈칸이 아랫줄이면 윗줄이 이미 찼다는 뜻이라 불가능)
    if (y == 0 && board[1][x] == 0) {
        board[0][x] = board[1][x] = 'V';
        search();
        board[0][x] = board[1][x] = 0;   // 백트래킹
    }

    // 4) 가로 타일로 덮기
    if (x + 1 < n && board[y][x + 1] == 0) {
        board[y][x] = 'L';
        board[y][x + 1] = 'R';
        search();
        board[y][x] = board[y][x + 1] = 0;
    }
}
```

**5. 한계를 알고 쓴다.** 브루트포스는 타일링을 하나하나 다 만들어 보므로 걸리는 시간이 `F(n+1)`에 비례한다. `n = 20`이면 1만 개 남짓이라 순식간이지만 `n = 40`이면 1억 6천만 개라 현실적이지 않다. 또 브루트포스는 나머지 연산을 하지 않으므로 답이 `MOD`를 넘으면 비교 자체가 무의미해진다. `n ≤ 20`이면 둘 다 안전하다.

**6. 전체 타일링의 수도 함께 비교한다.** 여기서부터 어긋난다면 문제가 대칭 판정이 아니라 `tiling()`이나 열거 방식에 있다는 뜻이므로, 어디가 잘못됐는지 범위를 좁힐 수 있다.

## 정리

| 항목 | 접근 1: 전체 − 대칭 | 접근 2: 직접 세기 |
| --- | --- | --- |
| 핵심 아이디어 | 모든 타일링은 대칭 아니면 비대칭 | 양쪽 끝에서 동시에 만들어 나가기 |
| 조각 나누기 기준 | `n`의 홀짝, 가운데를 무엇으로 덮는가 | 양쪽 끝을 덮은 타일의 조합 |
| 홀수 `n` | `tiling(n) - tiling(n/2)` | — |
| 짝수 `n` | `tiling(n) - tiling(n/2) - tiling(n/2-1)` | — |
| 점화식 | — | `asym(w-2) + asym(w-4) + 2 × tiling(w-3)` |
| 완전성 | 모든 타일링은 대칭 아니면 비대칭 | 모든 비대칭 타일링은 (a)~(d) 중 하나에 속한다 |
| 배타성 | 대칭이면서 비대칭일 수는 없다 | 양쪽 끝의 조합이 다르면 다른 패턴이다 |
| 기저 사례 | — | `width ≤ 2`일 때 `0` |
| 주의할 점 | 뺄셈 결과가 음수가 되지 않도록 `MOD`를 더한 뒤 나머지 연산 | (c), (d)의 가운데는 대칭이어도 상관없음 |
| 시간 복잡도 | `O(n)` | `O(n)` |
