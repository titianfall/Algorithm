# 최대 증가 부분 수열: LIS

> 주어진 수열에서 몇 개의 원소를 골라 만든 증가 부분 수열 중, 길이가 가장 긴 것을 찾는 동적 계획법 문제다.

## 문제 설명

어떤 수열의 **부분 수열 subsequence**이란, 원래 수열에서 원소 몇 개를 골라 순서를 유지한 채 이어 붙여 만든 수열이다. 이때 고른 원소들이 앞에서부터 순서대로 계속 커진다면(strictly increasing) 이를 **증가 부분 수열 increasing subsequence**이라 한다.

예를 들어 수열 `[1, 2, 4]`나 `[1, 3, 4]`는 아래 수열의 증가 부분 수열이다.

```text
1 2 3 1 4
```

주어진 수열에서 얻을 수 있는 가장 긴 증가 부분 수열의 길이를 구하라. 이를 **최대 증가 부분 수열 longest increasing subsequence, LIS**이라 한다.

위 수열의 최대 증가 부분 수열은 `[1, 2, 3, 4]`이고, 그 길이는 `4`다.

## 입력

입력의 첫 줄에는 테스트 케이스의 수 `C`가 주어진다.

각 테스트 케이스의 첫 줄에는 수열의 길이 `n`이 주어진다. 이어지는 줄에는 수열의 원소 `n`개가 공백으로 구분되어 주어진다.

## 출력

각 테스트 케이스마다 한 줄에, 주어진 수열의 최대 증가 부분 수열의 길이를 출력한다.

## 예제

**입력**

```text
3
5
1 2 3 1 4
6
10 20 10 30 20 50
1
7
```

**출력**

```text
4
4
1
```

## 제한

| 항목 | 제한 |
| --- | --- |
| 시간 제한 | 2초 |
| 메모리 제한 | 64MB |
| 수열의 길이 `n` | 1 이상 500 이하 |
| 각 원소의 값 | -1,000,000 이상 1,000,000 이하의 정수 |
| 테스트 케이스 수 `C` | 1 이상 50 이하 |

## 접근

풀이는 다음 순서로 발전시켜 나갑니다.

1. **완전 탐색** — 모든 증가 부분 수열을 만들어 보는 재귀 함수를 세운다.
2. **입력 손보기** — 부분 문제의 정의를 바꿔 메모이제이션이 가능하도록 만든다. → `O(n²)`
3. **시작 위치 고정하기** — 가상의 시작점을 두어 코드를 더 간결하게 만든다.
4. **더 빠른 해법** — 이분 탐색으로 `O(n log n)`까지 줄인다.

### 1. 완전 탐색으로 시작하기

최대 증가 부분 수열을 찾는 문제를 숫자 하나씩을 선택하는 조각으로 나눈 뒤, 각 조각에서 숫자 하나씩을 고르는 완전 탐색 알고리즘을 만듭니다. 수열 `A`를 입력받아 LIS의 길이를 반환하는 재귀 함수 `lis(A)`는, `A`의 모든 증가 부분 수열을 만들어 본 뒤 그중 가장 긴 것의 길이를 반환합니다.

`A[i]`를 시작 숫자로 골랐다고 합시다. 그 뒤에 올 수 있는 숫자는 `A[i]`보다 뒤에 있으면서 값이 더 큰 숫자들뿐입니다. 이 숫자들만 모아 만든 수열을 `B`라 하면, `B`에서 얻은 LIS 앞에 `A[i]`를 붙여 `A[i]`부터 시작하는 LIS를 얻을 수 있습니다.

이때 `B`의 LIS를 구하는 데에는 `A[i]`나 그 이전에 고른 숫자들을 알 필요가 없습니다. 즉, 부분 문제 `B`의 최적해가 곧 전체 문제의 최적해로 이어집니다. **따라서 LIS에도 최적 부분 구조가 성립합니다.**

```cpp
int lis(const vector<int>& A) {
    // 기저 사례: A가 텅 비어 있을 때
    if (A.empty()) return 0;

    int ret = 0;
    for (int i = 0; i < A.size(); ++i) {
        // A[i]보다 뒤에 있으면서 더 큰 숫자들만 모아 B를 만든다.
        vector<int> B;
        for (int j = i + 1; j < A.size(); ++j) {
            if (A[i] < A[j]) B.push_back(A[j]);
        }
        // A[i] 한 개(+1)에 B의 LIS를 이어 붙인다.
        ret = max(ret, 1 + lis(B));
    }
    return ret;
}
```

### 2. 입력 손보기

이 코드는 완전 탐색으로서의 기능은 잘 수행하지만, 메모이제이션을 적용하기는 까다롭습니다. 입력이 정수가 아니라 정수의 배열이기 때문입니다. STL의 `map` 같은 연관 배열을 쓰면 메모이제이션이 가능하기는 합니다만, 엄청나게 느리기 때문에 최후의 수단으로 남겨 둡니다.

`A`의 정의를 되짚어, `A`를 좀 더 간단하게 표현하는 방법을 생각해 봅시다. `lis(A)`에 넘어오는 `A`는 항상 다음 두 가지 중 하나가 됩니다.

1. 원래 주어진 수열 `S` 전체
2. 어떤 원소 `S[i]`에 대해, `S[i]` 뒤에 있으면서 `S[i]`보다 큰 원소들만 포함하는 부분 수열

특히 2번의 경우, 이전에 고른 숫자들은 정의에 포함되지 않는다는 점에 유의하세요. 이전에 고른 숫자들은 어차피 마지막에 고른 숫자보다 앞에 있고 값도 작습니다. 따라서 "뒤에 있고 값이 더 커야 한다"는 조건은 2번 조건만으로 이미 만족됩니다.

이렇게 보면 2번에 해당하는 `A`는 `S`의 인덱스와 1:1로 대응되고, `A`로 주어지는 입력은 전부 `n + 1`가지뿐입니다. 이를 이용해 부분 문제의 정의를 아예 다음과 같이 바꿀 수 있습니다.

> `lis2(start)` = `S[start]`에서 시작하는 증가 부분 수열 중 최대 길이

재귀 호출을 할 때마다 `S[start]`보다 뒤에 있고 값이 큰 숫자 중 하나를 다음 숫자로 정한 뒤, 거기서 시작하는 증가 부분 수열의 최댓값을 구하게 됩니다.

```cpp
int n;
int cache[100], S[100];

// S[start]에서 시작하는 증가 부분 수열 중 최대 길이를 반환한다.
int lis2(int start) {
    int& ret = cache[start];
    if (ret != -1) return ret;

    // S[start]는 항상 포함되므로 길이는 최소 1이다.
    ret = 1;
    for (int next = start + 1; next < n; ++next) {
        if (S[start] < S[next]) {
            ret = max(ret, lis2(next) + 1);
        }
    }
    return ret;
}
```

별도의 기저 사례 없이, 뒤에 더 이을 숫자가 없을 때도 `for`문을 그대로 순회하는 점을 눈여겨보세요. 이 경우 재귀 호출이 한 번도 일어나지 않으므로 `ret`은 초깃값 그대로 1이 됩니다.

시간 복잡도는 부분 문제의 수와 하나당 연산량을 곱해 구합니다. 부분 문제 `start`는 총 `O(n)`개이고, 각 부분 문제에서 `O(n)`짜리 반복문을 순회하므로, 전체 시간 복잡도는 `O(n) × O(n) = O(n²)`입니다.

### 3. 시작 위치 고정하기

`lis2()`를 호출할 때는 항상 증가 부분 수열의 시작 위치를 지정해 줘야 하므로, 처음에는 각 위치를 순회하며 최댓값을 찾는 코드가 필요합니다.

```cpp
int maxLen = 0;
for (int begin = 0; begin < n; ++begin) {
    maxLen = max(maxLen, lis2(begin));
}
```

이마저 번거롭다면 간단한 변형으로 이 코드를 없앨 수 있습니다. 맨 앞에 `S[-1] = -∞`인 가상의 원소가 있다고 치면, `lis3(-1)`을 호출하는 것만으로 항상 모든 시작 위치를 자동으로 시도하게 됩니다.

```cpp
int n;
int cache[101], S[100]; // start = -1이 쓰일 수 있으므로 캐시를 한 칸 늘린다.

// S[start]에서 시작하는 증가 부분 수열 중 최대 길이를 반환한다.
int lis3(int start) {
    int& ret = cache[start + 1]; // 음수 인덱스를 피하려 start + 1로 접근한다.
    if (ret != -1) return ret;

    // S[start]는 항상 포함되므로 길이는 최소 1이다.
    ret = 1;
    for (int next = start + 1; next < n; ++next) {
        if (start == -1 || S[start] < S[next]) {
            ret = max(ret, lis3(next) + 1);
        }
    }
    return ret;
}
```

가상의 원소 `S[-1]`은 실제 수열에 포함되지 않으므로, 최종 답으로는 `lis3(-1) - 1`을 사용하면 됩니다.

### 4. 더 빠른 해법

사실 `O(n²)`이 LIS를 찾는 가장 빠른 방법은 아닙니다. `O(n log n)` 시간에 해결하는 방법이 존재합니다.

이 알고리즘은 텅 빈 수열에서 시작해 숫자를 하나씩 추가해 나가며, 각 길이의 증가 수열 중 마지막 수가 가장 작은 것이 무엇인지를 추적합니다.

`S`의 첫 다섯 원소가 `{5, 6, 7, 1, 2}`라고 합시다.

- 길이가 3인 증가 부분 수열은 `{5, 6, 7}` 하나뿐입니다.
- 길이가 2인 증가 부분 수열은 `{5, 6}`, `{6, 7}`, `{1, 2}` 셋이 있습니다.

이 중 가장 유리한 것은 마지막 값이 가장 작은 `{1, 2}`입니다. 다음 수로 `3`, `4`가 주어지는 경우를 생각해 보면, 마지막 값이 작을수록 더 많은 수를 뒤에 이어 붙일 수 있음을 쉽게 알 수 있습니다.

따라서 원소를 추가하는 과정에서 
> `C[i]`를 "지금까지 만든 부분 수열이 갖는, 길이 `i`인 증가 부분 수열의 마지막 값 중 최솟값"으로 정의해 코드를 개선하면, LIS의 길이 `K`에 대해 `O(NK)` 시간에 LIS를 찾을 수 있습니다.

여기서 한 발 더 나아가 `C[]`가 항상 순증가한다는 사실을 이용하면, `C[]`에 대해 이분 탐색을 수행함으로써 LIS를 `O(n log K) ≤ O(n log n)`에 찾는 알고리즘을 만들 수 있습니다.

```cpp
// 각 길이의 증가 수열 중 마지막 값의 최솟값을 C[]에 유지한다.
int lisFast() {
    vector<int> C;
    for (int i = 0; i < n; ++i) {
        // S[i]가 들어갈 자리를 이분 탐색으로 찾는다.
        auto it = lower_bound(C.begin(), C.end(), S[i]);
        if (it == C.end()) C.push_back(S[i]); // 가장 크면 길이를 늘린다
        else *it = S[i];                      // 아니면 그 자리를 갱신한다
    }
    return C.size();
}
```

`C[]`는 항상 정렬된 상태를 유지하므로 `lower_bound`로 `S[i]`가 들어갈 자리를 이분 탐색으로 찾을 수 있습니다. 그 자리가 `C`의 끝이면 `S[i]`가 지금까지의 어떤 값보다 커서 LIS를 한 칸 늘리는 경우이므로 뒤에 덧붙이고, 그렇지 않으면 같은 길이를 더 작은 마지막 값으로 갱신합니다. 모든 원소를 처리한 뒤 `C`의 길이가 곧 LIS의 길이입니다. 단, `C`에 남는 값들이 실제 LIS를 이루지는 않으므로 길이만 얻을 수 있다는 점에 유의하세요.

### 5. 최적화 문제 동적 계획법 레시피

지금까지의 과정을 최적화 문제 동적 계획법 레시피에 맞추어 되짚어 봅시다.

1. **완전 탐색 설계** — 모든 증가 부분 수열을 만들어 보고 그중 가장 긴 것의 길이를 반환하는 `lis()`를 만들었습니다.
2. **부분 문제 정의 바꾸기** — 전체 수열의 LIS가 아니라, `S[start]`에서 시작하는 부분 증가 수열의 최대 길이만 반환하도록 정의를 바꿨습니다.
3. **입력 걸러내기** — 정의를 바꾼 덕분에 이전에 고른 숫자들에 대한 정보를 넘길 필요가 없어졌습니다. 이는 LIS에 최적 부분 구조가 성립하기 때문입니다. 그 결과 입력이 시작 위치 `start` 하나로 줄어, 중복되는 부분 문제가 많이 생깁니다.
4. **입력을 정수로 바꾸기** — 완전 탐색의 입력은 정수 배열 `A`라서 그대로는 메모이제이션하기 어려웠습니다. `A`가 항상 `S`의 부분 수열이고 `S`의 인덱스와 1:1로 대응된다는 점을 이용해, 입력을 배열에서 정수 `start`로 바꿨습니다.
5. **메모이제이션** — `cache[start]`에 결과를 저장해 같은 부분 문제를 다시 계산하지 않도록 했습니다.
