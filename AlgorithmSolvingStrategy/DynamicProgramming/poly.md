# 폴리오미노: POLY

> 책 8.15절 「풀이: 폴리오미노」를 옮긴 노트다. `n`개의 정사각형으로 만들 수 있는 **세로 단조 폴리오미노**의 수를 세는 문제로, 최적화가 아니라 **경우의 수**를 세는 동적 계획법이다.

- 문제 ID: `POLY`
- 출처: [알고스팟 - 폴리오미노](https://algospot.com/judge/problem/read/POLY)
- 시간 제한: 2초
- 메모리 제한: 64MB

## 문제 설명

정사각형들의 변들이 서로 맞닿아 붙어 있는 도형을 **폴리오미노**라고 부른다. `n`개의 정사각형으로 구성된 폴리오미노를 `n`-폴리오미노라고 하며, 이들은 정사각형의 배치에 따라 여러 가지 모양을 가질 수 있다.

이 중 **세로로 단조인(monotone)** 폴리오미노만을 세려고 한다. 세로 단조 폴리오미노란 **어떤 가로줄도 폴리오미노를 두 번 이상 교차하지 않는** 폴리오미노를 말한다. 다시 말해, 각 가로줄에 포함된 정사각형들이 항상 하나의 덩어리로 연속해 있어야 한다.

칸이 채워진 자리를 `■`, 빈 자리를 `.`로 표시하면 다음과 같다.

```text
세로 단조인 폴리오미노        세로 단조가 아닌 폴리오미노

    ■ ■ ■                          ■ . ■
    ■ ■ .                          ■ ■ ■

    모든 가로줄이 한 덩어리        첫 줄이 두 덩어리로 끊긴다
```

`n`이 주어질 때 세로로 단조인 `n`-폴리오미노의 수를 계산하라. 이때 **회전하거나 뒤집어서 같아지는 폴리오미노들도 서로 다른 것으로 센다.**

## 입력

입력의 첫 줄에는 테스트 케이스의 수 `C` (`1 ≤ C ≤ 50`)가 주어진다.

각 테스트 케이스는 한 줄에 정사각형의 수 `n` (`1 ≤ n ≤ 100`)이 주어진다.

## 출력

각 테스트 케이스마다 한 줄에 세로로 단조인 `n`-폴리오미노의 수를 `10,000,000`으로 나눈 나머지를 출력한다.

## 예제

**입력**

```text
4
2
4
10
92
```

**출력**

```text
2
19
20727
4841817
```

`n = 2`일 때의 두 가지는 가로 도미노와 세로 도미노다. `n = 4`일 때의 19가지는 테트로미노(테트리스 조각)를 회전까지 구별해 센 수와 같다.

## 완전 탐색에서 시작하자

여기서 조건을 충족하는 모든 폴리오미노를 다 만들어 보는 완전 탐색에서부터 시작합시다. 여기에서는 어떤 순서대로 폴리오미노를 구성하는 정사각형들을 붙여 나갈지를 결정하는 것이 중요합니다. 같은 모양의 폴리오미노를 두 번 이상 세어서는 안 되기 때문이죠. 예를 들어 하나의 정사각형에서 시작해서 폴리오미노의 변들 중 하나에 다른 사각형을 붙여 나가는 방식으로 폴리오미노를 만든다고 하면, `2 × 2` 크기의 정사각형은 모두 열여섯(!) 번 세어지게 됩니다.

다행히 우리가 만드는 폴리오미노들이 모두 **세로 단조**라는 사실 때문에 문제가 간단해집니다. 세로 단조 폴리오미노에서, 각 가로줄에 포함된 정사각형들은 항상 일렬로 연속해 있습니다. 따라서 각 가로줄마다 몇 개의 정사각형을 넣을지를 결정하고, 이들을 왼쪽-오른쪽으로 적절히 밀어 주면 모든 폴리오미노를 만들 수 있습니다. (문제에 있는 예제로 확인해 보세요!)

`n`개의 정사각형으로 구성된 모든 폴리오미노들을 **첫 번째 가로줄에 포함된 정사각형의 수**를 기준으로 분류합시다. 그러면 모든 폴리오미노가 이 분류 중 정확히 하나에 포함되는 것을 쉽게 알 수 있지요. 각 분류에 속하는 폴리오미노들의 수를 모조리 더하면 우리가 원하는 답이 됩니다.

첫 줄에 `i`개의 정사각형이 있는 폴리오미노의 개수는 어떻게 구할 수 있을까요? 나머지 `n - i`개의 정사각형들로 폴리오미노를 만든 뒤, 이들을 적절히 맨 윗 줄 아래에 붙여 주면 되겠지요. 나머지 정사각형들로 만들 수 있는 폴리오미노의 수는 재귀 호출로 구할 수 있습니다. 다음과 같은 형태의 부분 문제를 이용하는 것이죠.

```text
poly(n) = n개의 정사각형으로 만들 수 있는 세로 단조 폴리오미노의 수를 반환한다.
```

## 붙이는 방법의 수까지 세어야 한다

그러나 이들을 붙일 수 있는 경우의 수를 고려하면 문제가 그렇게 단순하지는 않다는 것을 알 수 있습니다. 맨 윗줄과 나머지를 **어떻게 붙이느냐에 따라 다른 폴리오미노**가 되기 때문에, 이 경우의 수는 두 번째 줄에 포함된 정사각형의 수와 상관이 있기 때문이지요.

두 줄은 **적어도 한 칸에서는 위아래로 맞닿아야** 하므로, 아래 줄을 좌우로 밀 수 있는 범위가 곧 붙이는 방법의 수가 됩니다. 예를 들어 첫 줄과 두 번째 줄에 모두 두 개의 사각형이 있다면, 다음과 같이 세 가지 방법으로 이들을 붙일 수 있습니다.

```text
첫 줄 2개(▓) + 두 번째 줄 2개 → 3가지

① 아래 줄을 왼쪽 끝까지 민 경우 (겹치는 칸은 하나)

  ┌─┬─┐
  │▓│▓│
┌─┼─┼─┘
│ │ │
└─┴─┘

② 두 줄을 나란히 붙인 경우 (겹치는 칸은 둘)

┌─┬─┐
│▓│▓│
├─┼─┤
│ │ │
└─┴─┘

③ 아래 줄을 오른쪽 끝까지 민 경우 (겹치는 칸은 하나)

┌─┬─┐
│▓│▓│
└─┼─┼─┐
  │ │ │
  └─┴─┘
```

반면 첫 번째 줄에 하나의 사각형만 들어간다면 다음과 같은 두 가지 방법으로밖에 붙일 수 없지요.

```text
첫 줄 1개(▓) + 두 번째 줄 2개 → 2가지

① 아래 줄이 오른쪽으로 나온 경우

┌─┐
│▓│
├─┼─┐
│ │ │
└─┴─┘

② 아래 줄이 왼쪽으로 나온 경우

  ┌─┐
  │▓│
┌─┼─┤
│ │ │
└─┴─┘
```

따라서 경우의 수를 정확히 계산하기 위해서는 두 번째 줄, 그러니까 **나머지 사각형으로 만드는 폴리오미노의 첫 줄에 있는 정사각형의 수**를 별도로 지정할 수 있어야 합니다. 이를 구현하기 위한 여러 방법이 있지만, 이 중 직관적인 것은 부분 문제의 정의에 **폴리오미노의 첫 줄에 들어갈 정사각형의 수 `first`를 추가**하는 것입니다. 그러면 다음과 같은 부분 문제 정의를 얻을 수 있지요.

```text
poly(n, first) = n개의 정사각형을 포함하되,
                 첫 줄에 first개의 정사각형을 갖는 세로 단조 폴리오미노의 수
```

## 점화식 세우기

`poly(n, first)`는 어떻게 계산할까요? 첫 줄에 들어갈 정사각형의 수가 정해져 있으니, 이제 남은 `n - first`개의 정사각형들로 어떻게 폴리오미노를 만들 수 있는지를 생각해 봅시다. 이 폴리오미노들의 수는 다음 식으로 표현할 수 있지요.

```text
poly(n - first, 1) + poly(n - first, 2) + ... + poly(n - first, n - first)
```

이때 두 번째 줄에 있는 정사각형의 수에 따라 이들을 붙일 수 있는 방법의 수가 정해집니다. 예를 들어 맨 윗 줄에 두 개의 정사각형을 두기로 했다고 하죠. 나머지 정사각형들로 다음과 같은 폴리오미노를 만들었다고 합시다.

```text
남은 정사각형으로 만든 폴리오미노 (첫 줄에 3개)

┌─┬─┬─┐
│ │ │ │
├─┼─┼─┘
│ │ │
└─┴─┘
```

그러면 맨 윗 줄과 이 폴리오미노를 다음과 같이 **네 가지 형태**로 붙일 수 있습니다.

```text
첫 줄 2개(▓) + 아래 폴리오미노의 첫 줄 3개 → 2 + 3 - 1 = 4가지

① 맨 윗 줄을 왼쪽 끝까지 민 경우

┌─┬─┐
│▓│▓│
└─┼─┼─┬─┐
  │ │ │ │
  ├─┼─┼─┘
  │ │ │
  └─┴─┘

②

  ┌─┬─┐
  │▓│▓│
  ├─┼─┼─┐
  │ │ │ │
  ├─┼─┼─┘
  │ │ │
  └─┴─┘

③

    ┌─┬─┐
    │▓│▓│
  ┌─┼─┼─┤
  │ │ │ │
  ├─┼─┼─┘
  │ │ │
  └─┴─┘

④ 맨 윗 줄을 오른쪽 끝까지 민 경우

      ┌─┬─┐
      │▓│▓│
  ┌─┬─┼─┼─┘
  │ │ │ │
  ├─┼─┼─┘
  │ │ │
  └─┴─┘
```

이것을 일반화하면 첫 줄에 `first`개의 정사각형이 있고, 나머지 사각형으로 만드는 폴리오미노의 첫 줄에 `second`개의 정사각형이 있다고 할 때, 이들을 붙일 수 있는 방법의 수는 **`first + second - 1`**이라는 사실을 알 수 있습니다. 따라서 위 식의 각 항마다 폴리오미노들을 붙일 수 있는 방법의 수를 곱해 주면 다음과 같은 수식을 얻을 수 있습니다.

```text
first × poly(n - first, 1) + (first + 1) × poly(n - first, 2) + ...
    + (n - 1) × poly(n - first, n - first)
```

이때 `n`과 `first`는 각각 `[0, 100]` 범위 내의 정수이므로 쉽게 메모이제이션을 적용해서 동적 계획법 알고리즘으로 바꿀 수 있습니다. 점화식은 다음과 같습니다.

```text
                    n - first
poly(n, first) =       Σ        (second + first - 1) × poly(n - first, second)
                    second = 1
```

## 코드 8.21 폴리오미노의 수 구하기

```cpp
const int MOD = 10 * 1000 * 1000;
int cache[101][101];

// n개의 정사각형으로 이루어졌고, 맨 위 가로줄에 first개의
// 정사각형을 포함하는 폴리오미노의 수를 반환한다.
int poly(int n, int first) {
    // 기저 사례: n == first
    if (n == first) return 1;

    // 메모이제이션
    int& ret = cache[n][first];
    if (ret != -1) return ret;

    ret = 0;
    for (int second = 1; second <= n - first; ++second) {
        int add = second + first - 1;
        add *= poly(n - first, second);
        add %= MOD;
        ret += add;
        ret %= MOD;
    }
    return ret;
}
```

코드 8.21은 이 점화식을 직접 코드로 옮긴 것입니다. 중간 계산 과정에서 **오버플로가 발생하지 않는지 여부**를 유의해 보세요. 오버플로가 발생할 가능성이 있는 곳은 `(second + first - 1) × poly(n - first, second)`의 곱셈인데, 이때 `poly()`의 반환 값은 1천만 미만이고 `(second + first - 1)`은 100 미만이므로 이 곱셈의 결과는 최대 10억으로 `2^31 - 1`을 초과하지 않습니다.

### 가장 큰 수를 직접 대입해 보기

말로만 보면 감이 안 오니, 각 항이 가질 수 있는 **최댓값을 실제로 넣어** 봅시다.

**① 배수 `second + first - 1`의 최댓값은 99다.**

루프 조건이 `second <= n - first`이므로 `second + first`는 아무리 커도 `n`을 넘지 못합니다. 문제에서 `n <= 100`이니

```text
second + first - 1  <=  n - 1  <=  100 - 1  =  99
```

`first`와 `second`가 각각 100까지 갈 수 있으니 둘을 더해 200이라고 생각하기 쉽지만, **둘의 합 자체가 `n` 이하로 묶여 있다**는 점이 핵심입니다.

**② `poly()`의 반환 값 최댓값은 9,999,999다.**

반환 직전에 `ret %= MOD`를 하므로 `0`부터 `MOD - 1`까지만 나옵니다.

```text
MOD - 1 = 10,000,000 - 1 = 9,999,999
```

**③ 둘을 곱해 본다.**

```text
        99 × 9,999,999 =   989,999,901   ← 곱셈이 만들 수 있는 최댓값
   int의 최댓값 2^31 - 1 = 2,147,483,647
                  남는 여유 = 1,157,483,746
```

약 9.9억이라 `int` 한계의 절반도 쓰지 않습니다.

**④ 실제로 돌려 보면 이보다도 작다.**

`n = 1..100`을 모두 계산하면서 곱셈 결과를 관찰하면, 두 최댓값이 동시에 일어나는 일은 없어서 실제 최댓값은 상한보다 더 작습니다.

```text
관찰된 최대 곱  : 866,283,012
발생 지점       : poly(100, 42)의 second = 46
계산            : 87 × 9,957,276 = 866,283,012
```

**⑤ 누적 `ret += add`도 안전하다.**

`add`는 더하기 전에 `add %= MOD`를 거치므로 `9,999,999` 이하이고, `ret` 역시 매번 `ret %= MOD`로 줄여 두므로 `9,999,999` 이하입니다.

```text
   9,999,999 + 9,999,999 = 19,999,998   ← 더하기가 만들 수 있는 최댓값
             실제 관찰 최댓값 = 19,961,551
```

**⑥ 조건이 조금만 달랐다면 터진다.**

이 안전 마진은 `MOD`가 1천만이라서 생긴 것입니다. 만약 `MOD`를 1억으로 잡았다면

```text
99 × 99,999,999 = 9,899,999,901  >  2,147,483,647   ← 오버플로
```

`int`를 4번 넘게 돌아 음수가 나옵니다. "곱하는 두 값의 상한을 각각 구해서 곱해 본다"는 확인을 습관처럼 해야 하는 이유입니다.

## 시간 복잡도

마지막으로 이 알고리즘의 시간 복잡도를 분석해 봅시다. 가능한 `n`과 `first`의 조합의 수는 `O(n^2)`이고, `poly()`를 한 번 계산하는 데는 `O(n)`의 시간이 들기 때문에 전체 시간 복잡도는 **`O(n^3)`**이 됩니다.

## 다시 볼 포인트

- 경우의 수를 셀 때는 **분류가 서로 겹치지 않도록** 기준을 정해야 한다. 여기서는 "첫 가로줄에 들어간 정사각형의 수"가 그 기준이다.
- 부분 문제를 재귀 호출로 쪼갤 때, **두 조각을 이어 붙이는 방법의 수**도 함께 세야 한다. 이 문제에서는 그 값이 아래 조각의 첫 줄 크기에 의존하므로, 부분 문제 정의에 `first`를 추가해 그 정보를 상태로 끌어올렸다.
- 경우의 수 문제는 답이 쉽게 커지므로 `MOD`로 나눈 나머지를 반환하되, **중간 곱셈이 `int` 범위를 넘지 않는지** 곱하는 두 값의 상한을 각각 구해 직접 곱해 본다. 여기서는 `99 × 9,999,999 = 989,999,901`로 `2^31 - 1`의 절반도 되지 않는다.
- 변수 하나하나의 범위(`first <= 100`, `second <= 100`)가 아니라 **루프 조건이 걸어 두는 관계**(`second <= n - first`, 즉 `second + first <= n`)를 봐야 진짜 상한이 나온다. 여기서는 그 차이가 200과 99다.
