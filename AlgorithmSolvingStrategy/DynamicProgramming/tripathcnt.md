# 삼각형 위의 최대 경로 개수 세기: TRIPATHCNT

> [삼각형 위의 최대 경로(TRIANGLEPATH)](<trianglePath.md>)에서 구한 것은 최대 경로의 **합**이었다. 이 문제는 그 최대 합을 만드는 **경로가 몇 개인지**를 센다.

## 문제 설명

정수들이 삼각형 모양으로 주어진다. 꼭대기에서 출발해 맨 아래 줄까지 내려가며, 현재 위치가 `(y, x)`라면 다음 줄의 `(y + 1, x)` 또는 `(y + 1, x + 1)`로만 이동할 수 있다.

지나간 수의 합이 최대가 되는 경로를 **최대 경로**라고 하자. 최대 경로는 유일하지 않을 수 있다. 주어진 삼각형에서 최대 경로가 모두 몇 개인지 세어야 한다.

```text
      9
     5 7
    1 3 2
   3 5 5 6
```

이 삼각형에서 최대 경로 합은 `24`이고, 합이 `24`인 경로는 세 개다.

- `9 → 7 → 3 → 5` (왼쪽 5)
- `9 → 7 → 3 → 5` (오른쪽 5)
- `9 → 7 → 2 → 6`

가운데 두 경로는 지나간 숫자의 나열이 `{9, 7, 3, 5}`로 같지만, 마지막 줄에서 서로 다른 칸에 도착하므로 **다른 경로**로 센다. 즉 세는 대상은 숫자의 조합이 아니라 이동 경로 자체다.

## 입력

입력의 첫 줄에는 테스트 케이스의 수 `C`가 주어진다.

각 테스트 케이스의 첫 줄에는 삼각형의 크기 `n`이 주어진다. 이어지는 `n`개의 줄에는 위에서부터 각 줄의 숫자가 주어지며, `i`번째 줄에는 정확히 `i`개의 정수가 있다.

## 출력

각 테스트 케이스마다 한 줄에 최대 경로의 개수를 출력한다.

## 예제

**입력**

```text
1
4
9
5 7
1 3 2
3 5 5 6
```

**출력**

```text
3
```

## 제한

| 항목 | 제한 |
| --- | --- |
| 시간 제한 | 5초 |
| 메모리 제한 | 64MB |
| 테스트 케이스 수 `C` | 1 이상 50 이하 |
| 삼각형의 크기 `n` | 2 이상 100 이하 |
| 각 칸의 수 | 1 이상 100,000 이하의 자연수 |

> 최대 경로의 개수는 이론적으로 `2^(n-1)`까지 커질 수 있다. 책의 구현은 `int`를 사용하므로 정답이 32비트 정수 범위에 들어온다고 보지만, 확신이 없다면 `long long`으로 두는 편이 안전하다.

## 접근

### 이미 푼 문제를 부품으로 쓰기

먼저 각 칸에서 시작하는 최대 경로 합을 알아야 한다. 이것은 TRIANGLEPATH에서 이미 해결했다.

```text
path2(y, x) = (y, x)에서 시작해 맨 아래 줄까지 내려가는 부분 경로의 최대 합
```

예제 삼각형에 `path2()`를 적용하면 다음과 같다.

```text
    (a) 입력            (b) path2()
      9                    24
     5 7                 13 15
    1 3 2                6 8 8
   3 5 5 6              3 5 5 6
```

동적 계획법 문제를 풀 때, 각 부분 문제마다 최적해를 구하는 알고리즘을 미리 만들어 두면 그 위에 다른 문제를 얹기 쉬워진다. 여기서는 `path2()`가 각 위치의 "앞으로 얻을 수 있는 최댓값"을 알려주는 나침반 역할을 한다.

### 최대 경로의 개수 정의하기

```text
count(y, x) = (y, x)에서 시작해 맨 아래 줄까지 내려가는 최대 경로의 개수
```

`(y, x)`에서 내려갈 수 있는 두 칸의 최대 합 `path2(y + 1, x)`와 `path2(y + 1, x + 1)`을 비교하자.

- 왼쪽이 더 크면, 최대 경로는 반드시 왼쪽으로 내려간다 → `count(y + 1, x)`
- 오른쪽이 더 크면, 최대 경로는 반드시 오른쪽으로 내려간다 → `count(y + 1, x + 1)`
- 두 값이 같으면, 어느 쪽으로 가도 최대 경로를 만들 수 있다 → 두 경우의 수를 **더한다**

```text
count(y, x) =
    count(y+1, x)                          if path2(y+1, x) > path2(y+1, x+1)
    count(y+1, x+1)                        if path2(y+1, x) < path2(y+1, x+1)
    count(y+1, x) + count(y+1, x+1)        if path2(y+1, x) = path2(y+1, x+1)
```

여기서도 **완전성**과 **배타성**이 성립한다. 최대 경로는 반드시 왼쪽 아래나 오른쪽 아래 중 한쪽으로만 내려가므로, 누락도 중복도 없다.

기저 사례는 맨 아래 줄에 도착한 경우다. 더 이상 갈 곳이 없으므로 "아무 데도 가지 않는" 경로 한 개가 있는 셈이고, `1`을 반환한다. 이렇게 하면 각 경로가 마지막 줄에서 정확히 한 번씩 세어진다.

### 구현

세 갈래 조건문 대신 `>=`와 `<=`를 각각 검사하면, 두 값이 같을 때 양쪽이 모두 참이 되어 자연스럽게 합이 된다.

```cpp
int countCache[100][100];

// (y, x)에서 시작해서 맨 아래 줄까지 내려가는 최대 경로의 개수를 반환한다.
int count(int y, int x) {
    // 기저 사례: 맨 아래 줄에 도달한 경우
    if (y == n - 1) return 1;

    // 메모이제이션
    int& ret = countCache[y][x];
    if (ret != -1) return ret;

    ret = 0;
    if (path2(y + 1, x + 1) >= path2(y + 1, x)) ret += count(y + 1, x + 1);
    if (path2(y + 1, x + 1) <= path2(y + 1, x)) ret += count(y + 1, x);
    return ret;
}
```

테스트 케이스마다 **두 캐시를 모두** 초기화해야 한다. 하나라도 남겨 두면 이전 삼각형의 값이 섞인다.

```cpp
memset(cache, -1, sizeof(cache));        // path2()용
memset(countCache, -1, sizeof(countCache));
cout << count(0, 0) << '\n';
```

`path2()` 역시 메모이제이션되어 있으므로, `count()` 안에서 여러 번 호출해도 실제 계산은 칸마다 한 번씩만 일어난다.

### 시간 복잡도

- 부분 문제 `(y, x)`의 수는 삼각형의 칸 수와 같으므로 `O(n²)`
- 각 부분 문제에서 `path2()` 비교와 덧셈만 하므로 `O(1)`

전체 시간 복잡도는 `O(n²)`이고, 공간 복잡도도 캐시 두 개를 쓰므로 `O(n²)`이다.

## 정리

| 항목 | 내용 |
| --- | --- |
| 선행 문제 | `path2(y, x)` — 각 칸에서 시작하는 최대 경로 합 |
| 조각 나누기 기준 | 최대 경로가 왼쪽 아래로 가는가, 오른쪽 아래로 가는가 |
| 완전성 | 최대 경로는 반드시 둘 중 한쪽으로 내려간다 |
| 배타성 | 한 경로가 양쪽으로 동시에 내려갈 수는 없다 |
| 기저 사례 | 맨 아래 줄에서 `1` |
| 자주 하는 실수 | 테스트 케이스마다 캐시 두 개를 모두 초기화하지 않는 것 |
