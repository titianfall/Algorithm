# 와일드카드: WILDCARD

> 두 문자열의 대응 관계를 부분 문제로 쪼개 메모이제이션으로 판정하는 문제다. 해설은 추후 추가 예정.

## 문제 설명

**와일드카드**는 여러 개의 파일을 한꺼번에 가리킬 때 사용하는 특수 문자열이다. 와일드카드 패턴에는 일반적인 문자 외에 두 개의 특수 문자를 쓸 수 있다.

- `?` : 어떤 문자 **하나**와 대응한다.
- `*` : 어떤 문자열(**빈 문자열 포함, 길이 0 이상**)과 대응한다.

예를 들어 패턴 `he?p`는 `help`, `heap` 등과 대응하지만, `heeeeeep`과는 대응하지 않는다. 반면 `*p*`는 `p`, `help`, `papa`처럼 `p`를 포함하는 모든 문자열과 대응한다.

와일드카드 패턴과 함께 파일명의 목록이 주어질 때, 그중 패턴에 대응되는 파일명을 모두 찾아내라.

## 입력

입력의 첫 줄에는 테스트 케이스의 수 `C` (`1 ≤ C ≤ 10`)가 주어진다.

각 테스트 케이스의 첫 줄에는 와일드카드 패턴이 주어지고, 그 다음 줄에는 파일명의 수 `n` (`1 ≤ n ≤ 50`)이 주어진다. 이어지는 `n`개의 줄에 각각 파일명이 하나씩 주어진다.

- 패턴과 파일명의 길이는 각각 1 이상 100 이하다.
- 패턴은 알파벳 대소문자와 숫자, 그리고 `?`, `*`로 이루어진다.
- 파일명은 알파벳 대소문자와 숫자로만 이루어진다. (특수 문자 없음)

## 출력

각 테스트 케이스마다, 주어진 패턴에 대응되는 파일명을 **사전순**으로 정렬하여 한 줄에 하나씩 출력한다.

## 예제

**입력**

```text
3
*p*
3
help
papa
prg
*bb*
3
babbbc
bbbac
bccdd
********a
2
aaaaaaaaaaa
aaaaaaaaaab
```

**출력**

```text
help
papa
prg
babbbc
bbbac
aaaaaaaaaaa
```

> 세 번째 케이스의 `********a`는 `*`이 여러 개 이어져 있어, 메모이제이션이 없는 완전 탐색으로는 매칭 경로가 지수적으로 늘어나는 **최악의 경우**다. `aaaaaaaaaaa`는 `a`로 끝나므로 대응되지만, `aaaaaaaaaab`는 `b`로 끝나 대응되지 않는다.

## 접근

### 완전 탐색으로 시작하기

패턴 `w`가 문자열 `s`에 대응되는지를 반환하는 함수 `match(w, s)`를 생각하자. 앞에서부터 한 글자씩 맞춰 나가되, `?`나 서로 같은 글자는 그냥 지나가면 된다.

```cpp
// 와일드 카드 w가 원문 s에 대응되는지 여부를 반환
bool match(const string& w, const string& s) {
    int pos = 0;
    // ? 이거나 같은 글자인 동안 함께 전진
    while (pos < s.size() && pos < w.size() &&
           (w[pos] == '?' || w[pos] == s[pos]))
        ++pos;

    // 패턴 끝에 도달: 문자열도 끝났어야 대응된다.
    if (pos == w.size()) return pos == s.size();

    // *를 만난 경우: * 에 몇 글자를 대응할지 재귀로 확인
    if (w[pos] == '*')
        for (int skip = 0; pos + skip <= s.size(); ++skip)
            if (match(w.substr(pos + 1), s.substr(pos + skip)))
                return true;

    // 그 외(글자 불일치 / 문자열만 끝남)는 모두 실패
    return false;
}
```

### while문이 끝나는 네 가지 경우

`while`은 조건이 거짓이 되는 순간 멈춘다. 멈추는 이유는 다음 넷 중 하나다.

| 번호 | 멈추는 이유 | 처리 방법 |
| :---: | --- | --- |
| 1 | `w[pos]`와 `s[pos]`가 서로 다름 (불일치) | 마지막 `return false` |
| 2 | 패턴 `w`의 끝에 도달 | `if (pos == w.size())` — 문자열도 끝났으면 성공 |
| 3 | 문자열 `s`의 끝에 도달 | 마지막 `return false` |
| 4 | `w[pos]`가 `*` | `if (w[pos] == '*')` — 재귀로 몇 글자든 대응 |

핵심은 **2·4번만 명시적으로 처리하고, 1·3번은 따로 나누지 않고 마지막 `return false` 하나로 합쳐 처리**한다는 점이다. 두 경우 모두 결론이 "대응 실패"로 똑같기 때문이다.

> `*`은 **빈 문자열(0글자)에도 대응**되므로, `for`의 조건이 `pos + skip <= s.size()`처럼 `<=`여야 한다. `<`로 쓰면 `*`이 남은 문자열 전체를 삼키는 경우를 놓쳐, 예를 들어 패턴 `a*`가 문자열 `a`에 대응되지 못하는 버그가 생긴다.

### 중복되는 부분 문제

`match`는 지수적으로 느리다. `*`을 만날 때마다 `skip`을 0부터 끝까지 늘려 가며 재귀 호출하는데, 서로 다른 `skip`이 같은 `(w, s)` 상태로 이어지는 경우가 많기 때문이다. 예를 들어 [`********a` 패턴](<#예제>)처럼 `*`이 여러 개 이어지면 같은 부분 문제가 수없이 반복 호출된다.

대응 상태는 "**패턴에서 비교할 위치 `w`**"와 "**문자열에서 비교할 위치 `s`**" 두 정수만으로 완전히 결정된다. 즉 `match(w, s)`는 참조적 투명 함수이므로 [메모이제이션](<explain.md>)을 적용할 수 있다. 상태를 부분 문자열이 아니라 **인덱스 두 개**로 잡는 것이 핵심이다.

```cpp
int cache[101][101];   // -1로 초기화. 0: 실패, 1: 성공
string W, S;           // 패턴과 문자열은 전역으로 고정

bool matchMemoized(int w, int s) {
    int& ret = cache[w][s];
    if (ret != -1) return ret;

    while (s < S.size() && w < W.size() &&
           (W[w] == '?' || W[w] == S[s])) {
        ++w; ++s;
    }

    if (w == W.size()) return ret = (s == S.size());
    if (W[w] == '*')
        for (int skip = 0; s + skip <= S.size(); ++skip)
            if (matchMemoized(w + 1, s + skip))
                return ret = 1;
    return ret = 0;
}
```

파일명 `S`마다 대응 상태가 달라지므로, **각 파일명을 검사하기 전에 `memset(cache, -1, sizeof(cache));`로 캐시를 초기화**해야 한다.

### 시간 복잡도

메모이제이션의 시간 복잡도는 다음 식으로 계산한다.

```text
(존재하는 부분 문제의 수) × (한 부분 문제를 풀 때 필요한 반복문의 수행 횟수)
```

- 부분 문제 `(w, s)`의 개수: `O(|W| × |S|)`
- 각 부분 문제에서 `*`의 `for`문이 최대 `O(|S|)`번 돈다.

따라서 한 파일명당 시간 복잡도는 `O(|W| × |S|²)`이다. 패턴·파일명 길이가 100 이하이므로 완전 탐색의 지수 시간과 비교하면 충분히 빠르다.

### 다른 분해 방법: O(n²)번 분해

앞의 풀이는 부분 문제가 `O(|W| × |S|)`개인데, `*`을 만날 때마다 `for`문이 `O(|S|)`번 돌아 부분 문제 하나를 푸는 데 `O(|S|)`가 든다. 그래서 전체가 `O(|W| × |S|²)`이 된다. 이 `for`문을 없애면 각 부분 문제를 `O(1)`에 풀 수 있다.

핵심은 `*`이 대응하는 글자 수를 `for`로 전부 세는 대신, **딱 두 갈래로 쪼개는 것**이다.

- **`*`이 빈 문자열에 대응** → 패턴만 한 칸 전진: `match(w + 1, s)`
- **`*`이 한 글자 이상에 대응** → 문자열만 한 칸 전진(같은 `*`은 그대로 둠): `match(w, s + 1)`

`*`이 두 글자 이상을 먹는 경우는 `match(w, s + 1)`이 재귀적으로 다시 두 갈래로 쪼개지며 자연스럽게 처리된다. 즉 "한 번에 몇 글자?"라는 `O(|S|)`짜리 질문이 "한 글자 먹을까 말까?"라는 `O(1)` 질문으로 바뀐다.

여기에 더해, `?`나 같은 글자를 훑던 `while`문도 "한 글자씩 대응시키는 재귀 한 단계"로 흡수된다.

```cpp
int cache2[101][101];   // -1로 초기화

bool matchMemoized2(int w, int s) {
    int& ret = cache2[w][s];
    if (ret != -1) return ret;

    // 1. ? 이거나 같은 글자: 둘 다 한 칸 전진
    if (w < W.size() && s < S.size() && (W[w] == '?' || W[w] == S[s]))
        return ret = matchMemoized2(w + 1, s + 1);

    // 2. 패턴 끝: 문자열도 끝났어야 대응
    if (w == W.size()) return ret = (s == S.size());

    // 4. * : 빈 문자열에 대응(w+1, s) 또는 한 글자 이상에 대응(w, s+1)
    if (W[w] == '*')
        if (matchMemoized2(w + 1, s) ||
            (s < S.size() && matchMemoized2(w, s + 1)))
            return ret = 1;

    // 3. 그 외: 실패
    return ret = 0;
}
```

이제 부분 문제는 여전히 `O(|W| × |S|)`개지만, 각 부분 문제가 반복문 없이 `O(1)`에 처리된다. 따라서 전체 시간 복잡도는 다음과 같다.

```text
O(|W| × |S|) × O(1) = O(|W| × |S|)
```

`|W|`, `|S|`를 같은 규모 `n`으로 보면 `O(n²)`이다. 앞선 `O(n³)` 풀이보다 한 차수 빠르다.
